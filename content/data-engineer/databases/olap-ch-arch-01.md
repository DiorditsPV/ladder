## Вопрос
Как устроен ClickHouse и почему он быстр на аналитических запросах? Что такое движки таблиц, шарды и реплики?

## Ответ
ClickHouse — **колоночная аналитическая (OLAP) СУБД**, заточенная под массовые `SELECT`-агрегации по большим объёмам, а не под точечные OLTP-операции.

Почему быстр:
- **Колоночное хранение** — на диске каждая колонка отдельно: читаются только нужные столбцы, отличное сжатие однотипных данных (кодеки + LZ4/ZSTD).
- **Векторизованное исполнение** — обработка блоками по многу строк, эффективно по CPU-кэшу и SIMD.
- **Разреженный первичный индекс** по ключу сортировки + засечки (granules) → пропуск нечитаемых диапазонов; data skipping индексы.

**Движки таблиц** определяют, как хранятся/обрабатываются данные. Основной — семейство **MergeTree**: данные пишутся **партами**, фоном сливаются (merge), сортированы по `ORDER BY`; варианты ReplacingMergeTree, SummingMergeTree, AggregatingMergeTree. Есть интеграционные движки (Kafka, MySQL), Distributed.

**Масштабирование:** **шарды** (горизонтальное разбиение данных по узлам — параллелизм и объём) + **реплики** (копии шарда для надёжности и чтения), координация через ZooKeeper/Keeper. Слабые места: тяжёлые `JOIN`, частые точечные `UPDATE`/`DELETE` (мутации дорогие), не транзакционная OLTP-нагрузка.
