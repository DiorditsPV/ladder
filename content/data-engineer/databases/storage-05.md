## Вопрос
Чем объектное хранилище S3 отличается от файловой системы: bucket/key, «директории», модель консистентности?

## Ответ
S3 — **объектное** хранилище, не ФС:
- Данные = объекты (байты + метаданные), адресуются ключом (**key**) внутри **bucket**.
- Настоящих директорий **нет**: ключ вроде `data/dt=2026-05-01/part-0.parquet` — просто строка; «папки» эмулируются по разделителю `/`. Поэтому нет дешёвого rename/move каталога (это копирование объектов), а «листинг папки» = LIST по префиксу — платный и относительно медленный вызов.
- Нет частичной перезаписи/append: объект перезаписывается **целиком** (PUT), случайной записи в середину нет.
- **Консистентность:** с 2020 S3 даёт **strong read-after-write** для PUT/DELETE (раньше была eventual — отсюда исторические костыли). Но коммит-протоколы поверх «директорий» всё равно требуют осторожности.

Следствие для data engineering: S3 — дешёвое эластичное хранилище для data lake, но ФС-семантика (rename, append, atomic commit каталога) напрямую не работает.
