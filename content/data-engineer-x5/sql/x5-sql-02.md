## Задача
По той же таблице `bookings` выведи `building, floor, overall_price` — для каждого корпуса этаж с максимальной суммой `price` за 2024 год.

## Эталон
```sql
with per_floor as (
    select building, floor, sum(price) as overall_price
    from bookings
    where date >= date '2024-01-01' and date < date '2025-01-01'
    group by building, floor
)
select building, floor, overall_price
from per_floor
qualify row_number() over (partition by building order by overall_price desc) = 1;
```
Главное отличие от задачи про число клиентов — `partition by building`. Там искали одного глобального лидера, здесь — лидера внутри каждой группы, и именно секционирование окна выражает «топ внутри корпуса». Нужно уметь объяснить, где в запросе `partition by`, а где его нет и почему: в агрегате группировка идёт по паре `building, floor` (чтобы получить сумму по этажу), а в окне — только по `building` (чтобы нумеровать этажи внутри корпуса).

Вторая точка — сам агрегат: сумма `price`, а не количество строк; подмена `sum` на `count` — типичная смысловая ошибка, которую не видно по форме запроса. Третья — фильтр года полуоткрытым диапазоном по столбцу `date`, как и в первой задаче. Четвёртая — ничьи: `row_number` даст ровно один этаж на корпус, `rank` — все этажи с равной максимальной суммой; какой вариант нужен, определяет постановка, и это стоит спросить вслух.

Отдельно оценивается умеренность: задача решается одним CTE и одной оконной функцией. Три уровня вложенности, отдельные CTE под фильтр, под агрегат и под нумерацию — переусложнение, которое труднее читать и проверять. Без `QUALIFY` достаточно обернуть CTE в подзапрос с `where rn = 1`. Коррелированный подзапрос с `max()` тоже сработает, но читается хуже и на больших таблицах медленнее оконки.

Финальная самопроверка — прогнать запрос на двух-трёх строках: один корпус, два этажа, разные суммы — и убедиться, что в выдаче остался этаж с большей суммой, а сортировка идёт по убыванию.
