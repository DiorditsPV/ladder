## Вопрос
Как убрать shuffle из регулярного джойна двух больших таблиц по одному ключу с помощью бакетов и storage-partitioned join в Iceberg и когда это не окупится?

## Ответ
Shuffle из регулярного джойна можно убрать, если обе таблицы заранее разложены одинаково по ключу: тогда Spark читает бакет k обеих таблиц в одном таске и джойнит его без `Exchange`. В Iceberg это storage-partitioned join (SPJ): обе таблицы партиционируются одной функцией, например `bucket(64, client_id)` с одинаковым числом бакетов.

**Что нужно в Spark 3.5:**
- одинаковое преобразование в спецификации партиций обеих таблиц;
- равенство в условии джойна по каждой колонке партиционирования, которую читает запрос;
- два ключа, выключенные по умолчанию:
```python
spark.conf.set("spark.sql.sources.v2.bucketing.enabled", "true")
spark.conf.set("spark.sql.iceberg.planning.preserve-data-grouping", "true")
```
Проверка — под джойном в плане нет `Exchange`.

**Цена.** Таск джойна — это бакет целиком: число бакетов надолго задаёт параллелизм и размер таска, а сменить его — значит переписать таблицу. Shuffle не исчезает, а переезжает в запись: каждый писатель раскладывает данные по бакетам. Горячий ключ даёт гигантский бакет, и AQE тут не поможет — shuffle, который он умеет резать, отсутствует.

**Не окупится,** если одна сторона помещается в broadcast, если таблицы джойнят по разным ключам (бакеты помогают только одному), если джойн редкий. В Spark 4.x часть ограничений снимается отдельными настройками — проверь в своей версии.
