## Вопрос
Что такое перекос данных (skew) в Spark и почему из-за него один таск может держать весь стейдж?

## Ответ
Перекос данных (skew) — неравномерное распределение строк по ключу: у одного или нескольких значений ключа данных намного больше, чем у остальных.

После shuffle все строки с одинаковым ключом попадают в одну партицию, а партицию обрабатывает один таск. Если на один ключ приходится треть данных, его партиция в сотни раз больше соседних: остальные таски заканчивают за минуту, а этот работает час. Стейдж завершается только вместе с последним таском, поэтому весь джоб ждёт один перегруженный таск, пока ядра кластера простаивают. Такой таск к тому же чаще уходит в spill и падает по памяти.

Где перекос встречается:
- джойны по ключу с «горячим» значением — крупный клиент, популярный товар;
- мусорные значения ключа: `NULL`, `0`, `'unknown'`, тестовый аккаунт;
- оконные функции с `partitionBy` по такому ключу.

Пример: джойн событий с мерчантами по `merchant_id`, где один мерчант даёт половину событий, — одна партиция получит половину всех событий.

Перекос — свойство данных, а не настроек: добавление экзекьюторов не помогает, горячий ключ всё равно обрабатывает один таск.
