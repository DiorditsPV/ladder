## Вопрос
Что делать с перекосом, когда AQE не помогает: как работают salting, двухфазная агрегация и отдельная обработка горячего ключа?

## Ответ
Когда AQE не справляется — перекос в агрегации, окне или в джойне, за которым сразу идёт группировка по тому же ключу, — перекос лечат на уровне запроса.

**Salting для джойна.** К ключу большой стороны добавляют случайную соль 0…N-1, а маленькую сторону размножают N раз — по строке на каждую соль. Джойн идёт по паре `(key, salt)`, и горячий ключ делится на N тасков:
```python
big = events.withColumn("salt", (F.rand() * 16).cast("int"))
small = merchants.crossJoin(spark.range(16).withColumnRenamed("id", "salt"))
res = big.join(small, ["merchant_id", "salt"]).drop("salt")
```
Цена — лишние данные маленькой стороны и более сложный код. Для джойна с последующей группировкой есть вариант дешевле — `spark.sql.adaptive.forceOptimizeSkewedJoin=true`: AQE режет перекос ценой лишнего shuffle.

**Двухфазная агрегация.** Сначала агрегат по `(key, salt)`, затем по `key`. Работает для разложимых агрегатов — sum, count, min, max. Встроенные sum и count и так частично агрегируются до shuffle, так что им это обычно не нужно; помогает там, где частичной агрегации нет, например в pandas UDF. Медиана не разложима — вместо неё берут `percentile_approx`.

**Отдельная ветка для горячего ключа.** Строки горячего ключа обрабатывают отдельно, например broadcast-джойном, остальные — обычным путём, а результаты объединяют через `unionByName`.

Солить заранее «на всякий случай» не надо: лишний shuffle и размноженный справочник там, где AQE справился бы сам.
