## Вопрос
Что такое Catalyst и через какие планы проходит запрос, прежде чем превратиться в таски? Есть ли для оптимизатора разница, написан запрос через DataFrame API или через `spark.sql`?

## Ответ
Catalyst — оптимизатор Spark SQL: он представляет запрос деревом операторов и переписывает его правилами, пока не получится исполняемый план.

**Этапы.** Разобранный запрос → **analyzed**: имена таблиц и колонок сверены с каталогом, типы выведены → **optimized**: правила переписали дерево — фильтры и проекции опущены к источнику, константы свёрнуты, лишние колонки выброшены → **physical**: для каждого оператора выбрана реализация — стратегия джойна, вид агрегации, места для `Exchange` (shuffle). Напоследок whole-stage codegen склеивает цепочки операторов в одну сгенерированную Java-функцию; в плане такие операторы помечены `*(n)`, где n — номер склейки.

**DataFrame или SQL — без разницы.** Оба строят одно и то же логическое дерево, дальше путь общий, поэтому выбор между ними — вопрос читаемости кода, а не скорости.

Посмотреть все этапы:
```python
df = (spark.table("lake.sales.orders")
      .where("order_date = '2026-09-01'")
      .groupBy("store_id").count())
df.explain(mode="extended")
```
`extended` печатает parsed, analyzed, optimized и physical план; `formatted` — физический план с подробностями по каждому узлу, в том числе какие фильтры дошли до скана. В SQL то же самое — `EXPLAIN FORMATTED SELECT …`.
