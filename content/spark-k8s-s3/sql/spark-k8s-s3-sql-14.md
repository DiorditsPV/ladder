## Вопрос
Почему при записи с partitionBy получаются тысячи мелких файлов и что поставить перед записью: coalesce, repartition или REBALANCE?

## Ответ
Каждый таск пишет свой файл в каждую партицию таблицы, которая ему встретилась. Если перед записью 200 тасков, а строки каждого из 30 дней разбросаны по всем таскам, получится до 6000 файлов — даже если данных всего несколько гигабайт. Мелкие файлы потом медленно читаются и засоряют хранилище.

Лечится перераспределением перед записью, чтобы строки одного дня сходились в немногие таски.

**`coalesce(n)`** склеивает партиции без shuffle. Ловушка: n действует на весь стейдж, включая чтение и фильтрацию, — `coalesce(10)` заставит 10 тасков делать всю работу стейджа. Годится, только когда вход уже маленький.

**`repartition(n)`** — полный shuffle, скан остаётся параллельным. Без колонок строки раскладываются по кругу, и каждый таск снова получит кусок каждого дня. `repartition("event_date")` даёт по таску на день — зато большой день пишет один таск.

**`REBALANCE(event_date)`** — shuffle по колонке, после которого AQE склеивает мелкие куски и режет крупные до целевого размера: файлы ближе к нужному размеру, большой день пишут несколько тасков. Без AQE хинт игнорируется, а в PySpark 3.5 колонку ему можно передать только в SQL:
```python
df.createOrReplaceTempView("filtered")
out = spark.sql("SELECT /*+ REBALANCE(event_date) */ * FROM filtered")
out.write.partitionBy("event_date").parquet("s3a://lake/events/")
```
Для записи по партициям обычно лучший выбор — REBALANCE. В Iceberg-таблицу ничего добавлять не нужно: она сама запрашивает shuffle по партиции перед записью.
