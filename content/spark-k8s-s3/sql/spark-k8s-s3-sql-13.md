## Вопрос
Что происходит при записи DataFrame в партиционированную таблицу: как из тасков получаются файлы и от чего зависят их число и размер?

## Ответ
Файлы создают таски: на каждое значение партиции таблицы, которое встретилось таску, он пишет отдельный файл. Поэтому файлов примерно столько, сколько пар «таск × день» есть в последнем стейдже, плюс нарезка крупных файлов.

**Файловая запись (`partitionBy`, Parquet по пути).** Перед записью в плане стоит локальный `Sort` по колонкам партиционирования: строки таска упорядочены по дню, и открыт один файл за раз — кончился день, файл закрыт. Между тасками Spark сам ничего не перекладывает: как партиции пришли в последний стейдж, так и лягут.

**Iceberg.** Таблица сама сообщает Spark, как распределить строки перед записью, — свойство `write.distribution-mode`. По умолчанию это `hash`: перед записью в плане появляется `Exchange` по значению партиции, и строки одного дня сходятся в свои таски; целевой размер таска Iceberg задаёт сам (в 1.4+ около 384 МБ данных shuffle — из них после сжатия выходят файлы около 128 МБ), а AQE склеивает мелкие таски и режет крупные. Если у таблицы задан порядок сортировки — `range`: сэмплирование и глобальная сортировка, дороже. `none` — без shuffle: каждый таск пишет во все встреченные партиции.

Iceberg закрывает файл по `write.target-file-size-bytes` (512 МБ), но файл не бывает больше таска: для файлов крупнее 128 МБ поднимают `write.spark.advisory-partition-size-bytes`.

Если данные уже распределены правильно, свой `repartition` перед записью в Iceberg добавляет лишний второй shuffle.
