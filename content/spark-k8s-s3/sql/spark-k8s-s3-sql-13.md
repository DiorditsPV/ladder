## Вопрос
Что происходит внутри, когда DataFrame пишется в таблицу, партиционированную по дню: как из тасков получаются файлы и от чего зависит их число?

## Ответ
Файлы создают таски, каждый — свои: на каждое значение партиции таблицы, которое встретилось таску, он пишет отдельный файл. Поэтому файлов ≈ сумма по таскам числа разных дней в таске плюс нарезка крупных.

**Файловая запись (`partitionBy`, Parquet по пути).** Под `WriteFiles` в плане стоит локальный `Sort` по колонкам партиционирования: строки таска упорядочены по дню, и открыт один файл за раз — кончился день, файл закрыт. Между тасками Spark сам ничего не перекладывает: как партиции пришли в последний стейдж, так и лягут.

**Iceberg.** Таблица сама сообщает Spark, как распределить строки перед записью, — `write.distribution-mode`. По умолчанию (с Iceberg 1.2) это `hash`: перед записью в плане `Exchange` по значению партиции с пометкой `REBALANCE_PARTITIONS_BY_COL, 402653184`, и строки одного дня сходятся в свои таски. Число — advisory-размер от самого Iceberg (1.4+): 128 МБ × ожидаемое сжатие shuffle→Parquet, при lz4 и zstd — 384 МБ байтов shuffle; до него AQE склеивает мелкие таски и режет крупные. Если у таблицы задан порядок сортировки — `range`: сэмплирование и глобальная сортировка, дороже. `none` — без shuffle: каждый таск пишет во все встреченные партиции.

Iceberg закрывает файл на `write.target-file-size-bytes` (512 МБ), но файл не бывает больше таска: по умолчанию Iceberg целится в файлы около 128 МБ, для файлов крупнее подними `write.spark.advisory-partition-size-bytes` — он задаётся в байтах shuffle.
