## Вопрос
Как посмотреть план запроса в Spark и что в нём искать в первую очередь?

## Ответ
План смотрят через `df.explain()` или `EXPLAIN` в SQL. Удобнее всего режим `formatted`: сверху — дерево операций, ниже — подробности по каждому узлу. После запуска тот же план с реальными цифрами (строки, объёмы, время) есть во вкладке SQL в Spark UI.

```python
df.explain(mode="formatted")
```
Читают снизу вверх — от чтения данных к результату. В первую очередь ищут:
- **скан** (`FileScan`, `BatchScan`): какие колонки читаются и какие фильтры дошли до источника — `PushedFilters` у файлов, `filters=` у Iceberg; нужного фильтра там нет — читается лишнее;
- **Exchange** — это shuffle; каждый такой узел перемешивает данные по сети, и лишние Exchange — первый кандидат на оптимизацию;
- **стратегию джойна**: `BroadcastHashJoin` — маленькая сторона разослана экзекьюторам, `SortMergeJoin` — обе стороны перемешаны и отсортированы;
- **BatchEvalPython** или **ArrowEvalPython** — в этом месте данные уходят в Python UDF;
- **AdaptiveSparkPlan** в корне — включён AQE: до запуска план стартовый, итоговый (`isFinalPlan=true`) смотри в Spark UI после выполнения.

Полезная привычка перед тяжёлым джобом — открыть план и проверить три вещи: фильтры в скане, число Exchange и стратегии джойнов.
