## Вопрос
Почему фильтр из запроса может не дойти до чтения данных, как это увидеть в плане и как переписать условие?

## Ответ
Фильтр доходит до чтения данных (pushdown), только если источник может проверить его сам — по партициям и статистикам файлов. Источник понимает простые условия вида «колонка — оператор — значение» и их комбинации. Всё остальное остаётся в Spark над сканом, и читается вся таблица.

**Что мешает:**
- функция над колонкой: `date_format(event_ts, 'yyyy-MM-dd') = '2026-09-01'`, `substring(code, 1, 3) = 'abc'` — по метаданным такое не проверить;
- Python UDF в условии — чёрный ящик для оптимизатора: строки сначала уйдут в Python и только потом отфильтруются;
- неявное приведение типа: строковая колонка против числа (`store_code = 7`) превращается в `cast(store_code as int) = 7` и тоже не уходит в источник.

**Как увидеть.** В `explain(mode="formatted")` смотри не на отдельный `Filter` — он остаётся и при удачном pushdown, — а на описание скана: `PushedFilters` у файловых источников, `filters=` у Iceberg. Нужного условия там нет — оно не дошло. Во вкладке SQL видно и последствие: скан прочитал всю таблицу.

**Как переписать** — условием на самой колонке с литералом нужного типа:
```python
day = F.lit(run_date).cast("date")
df = (spark.table("lake.events.clicks")
      .where((F.col("event_ts") >= day) & (F.col("event_ts") < F.date_add(day, 1)))
      .where(F.col("region").isin("msk", "spb")))
```
