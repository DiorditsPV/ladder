## Вопрос
Как устроен CPython: что происходит при запуске скрипта, что такое байткод, объектная модель и GIL?

## Ответ
CPython — эталонная реализация Python на C.

- **Исполнение:** исходник компилируется в **байткод** (`.pyc` в `__pycache__`) — инструкции для стековой виртуальной машины; затем интерпретатор CPython выполняет байткод в цикле. То есть это компиляция-в-байткод + интерпретация, без машинного кода (JIT нет в обычном CPython; в 3.13+ появляется экспериментальный).
- **Объектная модель:** всё — объект (`PyObject`) с типом и счётчиком ссылок. Имена — это ссылки на объекты; переменные не «коробки», а метки. Изменяемые (list/dict) vs неизменяемые (int/str/tuple) типы → отсюда поведение при передаче в функции и копировании.
- **Управление памятью:** основной механизм — **подсчёт ссылок** (reference counting), плюс циклический сборщик мусора для разрыва ссылочных циклов; свой аллокатор (pymalloc).
- **GIL** (Global Interpreter Lock) — глобальная блокировка интерпретатора: в один момент байткод исполняет только один поток. Поэтому потоки **не дают параллелизма на CPU-bound** задачах (помогают на I/O-bound, где GIL отпускается на время ожидания). Для CPU-параллелизма — `multiprocessing`/нативные расширения; numpy/pandas отпускают GIL в C-коде. (В 3.13+ есть экспериментальный free-threaded build без GIL.)

Практические следствия: GIL → выбор между threading (I/O) и multiprocessing (CPU); ссылочная модель → осторожность с мутабельными значениями по умолчанию и shared state.
