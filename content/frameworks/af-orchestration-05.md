## Вопрос
Что такое XCom в Airflow, для чего он нужен и какие у него ограничения? Что делать, если между задачами нужно передать большой объём данных?

## Ответ
**XCom (cross-communication)** — механизм обмена *небольшими* значениями между задачами одного DAG-рана. Задача делает `xcom_push` (или просто возвращает значение из `execute`/`@task` — оно пушится автоматически под ключом `return_value`), другая — `xcom_pull` по `task_id`/`key`. В шаблонах доступно через `{{ ti.xcom_pull(...) }}`.

Хранится XCom **в метабазе Airflow** (таблица `xcom`), значение сериализуется (по умолчанию JSON, исторически pickle). Отсюда ограничения:
- значение должно быть сериализуемым и **маленьким** — это метаданные, а не транспорт для датасетов; большие объекты раздувают БД и бьют по производительности планировщика;
- лимит на размер зависит от типа колонки в БД (например, blob-лимиты в MySQL/Postgres).

Если нужно передать много данных — **передавай не данные, а ссылку**: путь в S3/HDFS, имя партиции/таблицы, ID объекта. Сами данные пишутся в хранилище, через XCom идёт только указатель. Для прозрачной работы с большими XCom есть **custom XCom backend** (например, бэкенд, который сам сохраняет payload в S3, а в метабазе держит только ссылку).
