## Вопрос
Какими настройками задаётся, сколько данные живут в топике, и как выбрать их для потока событий и для справочника?

## Ответ
Три настройки топика решают судьбу данных.

**`cleanup.policy`** — что делать со старым: `delete` (по умолчанию) выбрасывает старые сегменты целиком, `compact` оставляет последнее значение по каждому ключу, `compact,delete` сочетает оба.

**`retention.ms`** — сколько времени хранить (по умолчанию 7 суток). **`retention.bytes`** — сколько байт хранить на партицию, по умолчанию не ограничено. Если заданы оба, срабатывает тот, что наступит раньше. Считать надо на партицию: `retention.bytes=10GB` на топике из 24 партиций — это 240 ГБ данных плюс множитель репликации.

**`segment.ms` / `segment.bytes`** — когда закрывать текущий сегмент. Удаление работает только по закрытым сегментам, поэтому с суточным сегментом ретеншен в час не даст эффекта: данные уйдут не раньше, чем закроется сегмент.

Практический выбор: поток событий (клики, логи, транзакции) — `delete` и ретеншен по времени, достаточный для перечитывания при инциденте: обычно 3–7 дней, для критичных потоков — до срока разбора инцидента. Справочник или снимок состояния (текущий профиль клиента, актуальная цена) — `compact`: топик становится по сути ключ-значение хранилищем с историей изменений и не растёт бесконечно.

Изменение на живом топике: `kafka-configs.sh --bootstrap-server ... --alter --entity-type topics --entity-name orders --add-config retention.ms=259200000`.
