## Вопрос
Как Kafka Streams обращается со временем: чем event time отличается от stream time и что произойдёт с записью, опоздавшей на час?

## Ответ
**Event time** — время самого события, обычно метка времени записи Kafka или поле из данных, извлечённое `TimestampExtractor`. **Processing time** — момент обработки. Streams по умолчанию работает по event time, поэтому перечитывание вчерашних данных даст те же оконные результаты, что и вчера, — а по processing time всё схлопнулось бы в один момент.

**Stream time** — внутренние часы задачи: максимальный event time, встреченный на входе. Они не идут сами по себе, а двигаются только приходящими записями. Отсюда важное следствие: если поток замолчал, stream time стоит, и окно не закроется, пока не придёт новая запись с более поздним временем.

Порядок обработки: при чтении нескольких партиций задача выбирает следующей запись с наименьшей меткой времени, чтобы приблизиться к порядку по event time. Гарантии полного упорядочивания это не даёт.

**Окно и grace period.** Окно (`TimeWindows.ofSizeAndGrace`) собирает записи по интервалам event time. Grace period — сколько ещё ждать опоздавших после конца окна. Запись, пришедшая в пределах grace, попадает в своё окно и обновляет результат; пришедшая позже — отбрасывается и считается в метрике пропущенных записей. Запись, опоздавшая на час при grace в 10 минут, будет молча выброшена — поэтому эта метрика обязана быть на панели.

Компромисс прямой: больше grace — полнее результат, но позже он готов и больше состояния на диске.
