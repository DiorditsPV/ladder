## Вопрос
Какие настройки задают поведение приложения Kafka Streams и за что отвечает каждая — application.id, num.stream.threads, processing.guarantee, state.dir?

## Ответ
**`application.id`** — самая нагруженная настройка. Это одновременно `group.id` группы консьюмеров, префикс имён внутренних топиков (changelog и repartition) и идентификатор состояния на диске. Отсюда следствия: два приложения с одинаковым id считаются одним и делят между собой работу; смена id — это по сути новое приложение, которое стартует с чистого состояния и с `auto.offset.reset`; переиспользовать id погашенного приложения нельзя, не почистив его внутренние топики.

**`num.stream.threads`** — сколько потоков обработки в одном экземпляре. Единица параллелизма — задача, а задач ровно столько, сколько партиций в самом широком входном топике. Потоки сверх этого числа простаивают, как лишние консьюмеры в группе. Суммарно по всем экземплярам потоков тоже не должно быть больше числа задач.

**`processing.guarantee`** — `at_least_once` (по умолчанию) или `exactly_once_v2`. Второй включает транзакции: обновление состояния, запись в выходной топик и коммит offset'ов становятся атомарными. Цена — задержка, потому что результат виден читателю только после коммита транзакции, интервал которого задаётся `commit.interval.ms`.

**`state.dir`** — каталог локальных хранилищ (RocksDB). Должен лежать на постоянном диске: при потере каталога состояние восстанавливается из changelog-топика, а это минуты или часы. В Kubernetes — StatefulSet с томом, не Deployment.

Плюс `replication.factor` внутренних топиков: по умолчанию 1, в проде обязательно 3.
