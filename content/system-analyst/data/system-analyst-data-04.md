## Вопрос
Отчёт по выручке показывает сумму больше фактической, а число клиентов меньше ожидаемого. Как найти причину средствами SQL?

## Ответ
Оба симптома почти всегда объясняются двумя механизмами — размножением строк при соединении и особым поведением NULL.

**Размножение строк.** Если заказ соединён с позициями, у заказа из трёх позиций появятся три строки, и `SUM(o.total)` посчитает сумму заказа трижды. Проверка — сравнить количество строк до и после соединения:

```sql
SELECT COUNT(*) FROM orders WHERE created_at >= '2026-03-01';
SELECT COUNT(*) FROM orders o JOIN order_items i ON i.order_id = o.id WHERE o.created_at >= '2026-03-01';
```

Расхождение означает, что соединение не «один к одному». Лечится агрегацией по позициям в подзапросе или суммированием по `i.price * i.qty` вместо поля заказа.

**Поведение NULL.** `COUNT(column)` не считает NULL, `COUNT(*)` считает строки. Любое сравнение с NULL даёт неизвестность, поэтому `WHERE status <> 'cancelled'` молча отбрасывает строки, где статус не заполнен, — отсюда заниженное число клиентов. Правильно: `WHERE status IS DISTINCT FROM 'cancelled'` или явное `OR status IS NULL`.

Третий источник — дубли в самих данных: одна и та же сущность заведена дважды. Ищется группировкой по бизнес-ключу:

```sql
SELECT email, COUNT(*) FROM customers GROUP BY email HAVING COUNT(*) > 1;
```

Порядок разбора: сначала проверить кратность соединений, затем NULL в условиях, затем дубли в источнике. В отчёте всегда полезно указывать, что именно считается одной единицей — это снимает половину вопросов.
