## Вопрос
Нужно собрать отчёт по заказам с суммой по клиенту из двух таблиц (orders и customers) с группировкой — какие детали важно не упустить?

## Ответ
Первое решение — **тип JOIN**: если в отчёт должны попасть все клиенты, включая тех, у кого пока нет заказов (сумма 0), нужен `LEFT JOIN customers → orders`; если интересны только клиенты с заказами — `INNER JOIN`. Ошибка в выборе типа джойна — самая частая причина, когда отчёт «теряет» часть клиентов без явной ошибки выполнения.

Дальше — **GROUP BY и агрегаты**: сумма считается через `SUM(amount)`, группировка — по ключу клиента, и в SELECT можно указывать только колонки из GROUP BY или агрегатные функции — иначе СУБД либо откажет с ошибкой, либо (в MySQL без строгого режима) молча возьмёт произвольное значение из группы. Фильтрация по агрегату делается через **HAVING**, а не WHERE: `WHERE` отфильтровывает строки до группировки (например, только заказы за период), `HAVING` — уже готовые группы (например, только клиенты с суммой больше 10000).

Главная ловушка — **дублирование при джойне «один-ко-многим»**: если между orders и customers join идёт не напрямую, а через промежуточную таблицу с несколькими строками на заказ (например, order_items), сумма по заказу задвоится на количество строк в этой таблице; решение — либо агрегировать order_items в подзапросе до джойна с customers, либо использовать `DISTINCT`/оконные функции там, где это уместно, а не сырой JOIN с последующим SUM.

Дополнительно стоит проверить обработку NULL — `SUM` игнорирует NULL, а не считает как 0, что в LEFT JOIN без заказов даст NULL, а не 0, и это нужно явно обернуть в `COALESCE`, если отчёт ожидает нули.
