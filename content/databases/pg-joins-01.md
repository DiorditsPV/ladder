## Вопрос
Чем отличаются логические типы джойнов (INNER / LEFT / RIGHT / FULL / CROSS) от физических алгоритмов (nested loop / hash / merge join)? Как планировщик выбирает алгоритм?

## Ответ
**Логический тип** определяет семантику — какие строки попадают в результат:
- INNER — только совпавшие пары; LEFT/RIGHT OUTER — все строки одной стороны + NULL для несовпавших; FULL OUTER — все с обеих сторон; CROSS — декартово произведение.

**Физический алгоритм** определяет, КАК джойн исполняется (выбирает оптимизатор):
- **Nested loop** — для каждой строки внешней таблицы ищет совпадения во внутренней; хорош, когда одна сторона мала и/или есть индекс по ключу join.
- **Hash join** — строит хеш-таблицу по меньшей стороне и проходит большую; хорош для больших несортированных наборов в equi-join.
- **Merge join** — сортирует обе стороны (или берёт отсортированный вход/индекс) и сливает; хорош, когда входы уже отсортированы по ключу.

**Выбор:** планировщик оценивает кардинальности (по статистике `ANALYZE`), наличие индексов, размеры сторон и необходимость сортировки, затем берёт план с минимальной оценочной стоимостью (`EXPLAIN ANALYZE` показывает фактический). Логический тип и физический алгоритм **независимы**: один и тот же `LEFT JOIN` может выполниться любым из трёх алгоритмов.
