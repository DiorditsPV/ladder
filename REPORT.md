# Сервис интервью «граф вопросов» — отчёт-исследование + принятые решения

> Локальный веб-сервис для проведения технических интервью по стеку команды (дата-инженерия: прогноз спроса / time-series).
> Источник анализа стека: `/Users/user/dev/projects/work`. Исследование: 2026-05-29.
>
> Этот документ — **исследование и архитектурные решения** (почему такой стек и что в итоге построено).
> Пользовательская инструкция и формат контента — в `README.md`; карта репозитория и конвенции — в `AGENTS.md`.

---

## Часть 0. Краткое резюме (TL;DR)

- **Библиотека графа:** **React Flow (`@xyflow/react`)** — MIT, ноды = обычные React-компоненты (карточка вопроса + виджет оценки), встроены drag/zoom/pan/select. Авто-раскладку делает **не сам React Flow**, а внешний **Dagre/ELK** (подключается руками).
- **Архитектура:** **FastAPI + SQLite + React/Vite SPA**, запуск `uvicorn` локально, опционально упаковка в **pywebview**. Питон-бэкенд естественно читает `.md`/`.json` с диска и хранит оценки.
- **Импорт контента:** Markdown с **YAML-frontmatter** + JSON. На бэкенде — `python-frontmatter` + валидация схемы через **pydantic** (по образцу Astro Content Collections + Zod).
- **Раскрытие ноды:** **немодальный drawer** (боковая панель) — доска остаётся интерактивной; код в ответах — подсветка.
- **Два вида нод:** `kind: question` (теория) и `kind: task` (практическая задача с `starterCode`/`rubric`).
- **Раскладка — swimlanes, без рёбер.** Адаптивную маршрутизацию по score-conditional рёбрам (идея из CAT) **рассматривали и отвергли**: итог проще — доска карточек по направлениям × сложности, поле `edges` из модели удалено (см. §2.3).
- **Баланс тем** — из измеренного дисбаланса репозиториев (4 блока, веса ниже), сэмплирование пропорционально весам.

## Часть 1. Отчёт-исследование (с источниками)

Методология: 5 направлений → 24 источника → 113 утверждений → верификация топ-25 адверсариально (3 голоса, нужно 2/3 на опровержение) → 23 подтверждено, 2 убито.

### 1.1 Библиотека визуализации графа → **React Flow**

**Вывод:** React Flow (`@xyflow/react`) — рекомендованный выбор. *(confidence: high, 3-0)*
- MIT-лицензия, активно поддерживается с 2019, релизы вплоть до марта 2026, 36.8k★. — `reactflow.dev`, `github.com/xyflow/xyflow`
- Из коробки: drag, zoom, pan, multi-select, add/remove узлов/рёбер.
- **Ноды = стандартные React-компоненты** → можно встроить карточку вопроса с виджетом рейтинга/инпутами/чартами напрямую (закрывает требование «нода = вопрос+ответ+оценка»). — `reactflow.dev`
- ⚠️ **React Flow НЕ считает раскладку сам** — «we have not implemented our own layouting solution yet». Авто-раскладка делается через **Dagre** (пример `getLayoutedElements`) или **ELK** для сложных случаев. — `reactflow.dev/examples/layout/dagre`
- Альтернатива того же автора: **Svelte Flow** (MIT, релиз 2026-03-27) — если фронт на Svelte. По умолчанию берём React Flow (зрелее экосистема). — `xyflow.com`

**Прочие библиотеки:** Sigma.js — **плохо** для богатых кастомных карточек-нод: WebGL-рендерер ограничивает формы, раскладка/алгоритмы вынесены в отдельную `graphology`; сложнее Cytoscape.js/vis-network и куда сложнее React Flow. *(medium, 3-0)* — `pkgpulse.com`, `sigmajs.org`
- ⚠️ *Опровергнуто (1-2):* конкретные цифры «Canvas тянет 3-5k нод, WebGL 100k+». Для нашего масштаба (**сотни** нод) это неважно — любая из библиотек справится, выбор определяется удобством кастомных нод, где React Flow выигрывает.

### 1.2 Архитектура локального сервиса

**Что верифицировано:** только **pywebview** независимо подтверждён. *(high, 3-0)*
- BSD-лицензия, кросс-платформенная обёртка вокруг нативного webview (**без отдельного браузера**), **прямая двусторонняя связь JS↔Python без HTTP/REST** (`js_api`, `expose`, `evaluate_js`). — `pywebview.flowrl.com`, `github.com/r0x0r/pywebview`

> ⚠️ **Честный пробел исследования:** варианты «static SPA + IndexedDB», «SPA + FastAPI/SQLite», «Tauri/Electron» не получили независимо подтверждённых утверждений. Рекомендация ниже — инженерное суждение под контекст (Python-команда, single-user, импорт файлов с диска), а не верифицированный факт.

**Рекомендация — FastAPI + SQLite + React/Vite SPA (+ опц. pywebview):**
| Вариант | Плюсы | Минусы | Вердикт |
|---|---|---|---|
| Static SPA + IndexedDB | нет бэкенда | импорт файлов с диска неудобен, персист только в браузере | ❌ для «импорт .md/.json из директории» слабо |
| **SPA + FastAPI + SQLite** | **Python (родной стек), чтение `.md`/`.json` тривиально, SQLite-персист, REST для фронта** | нужен запуск `uvicorn` | ✅ **рекомендуется** |
| Tauri / Electron | десктоп-дистрибутив | Rust/JS, тяжелее, не нужно для single-user | ⚪ избыточно |
| pywebview-обёртка | десктоп-окно без браузера, остаёшься в Python | бандлинг фронта | ✅ **как опциональная упаковка** поверх FastAPI |

Команда — Python-heavy (Airflow/Spark/Django), поэтому бэкенд на Python снимает порог входа и делает импорт банка вопросов из директории нативным.

### 1.3 Импорт из Markdown / JSON

- **gray-matter** — де-факто парсер frontmatter: YAML по умолчанию, разделяет `data` и `content`. — `github.com/jonschlinkert/gray-matter`, `11ty.dev`. *(high, 3-0)*
  - 👉 На **Python-бэкенде** прямой аналог — **`python-frontmatter`** (+ `markdown-it-py` для рендера). Это и берём.
- **Astro Content Collections + Zod** — паттерн «схема валидирует каждую запись», `glob()`-лоадер тянет Markdown/MDX/JSON/YAML. — `docs.astro.build`. *(high, 3-0)*
  - 👉 Переносим на Python: **pydantic-модель** = схема ноды, валидируем каждый импортируемый файл (битый frontmatter → понятная ошибка).
- **mdbook-quiz** — минимальная схема банка (`questions[]`, вопрос требует `answer` + `prompt`) — хороший «скелет» полей. — `github.com/cognitive-engineering-lab/mdbook-quiz`. *(high, 3-0)*

### 1.4 UX раскрытия ноды

- **Немодальный диалог/drawer** перекрывает часть страницы, **не блокируя доступ к остальному** — доска остаётся интерактивной (в отличие от модалки). Требование доступности: фокусируемость и закрытие с клавиатуры. — W3C ARIA / MDN / NN/g. *(high, 3-0 / один пункт 2-1)*
- 👉 Реализация: боковой **drawer** для выбранной ноды (полный текст вопроса/ответа) + кнопка **«на весь экран»**. Markdown с подсветкой кода (SQL/PySpark/YAML).

### 1.5 Ограничения исследования (честно)

- Статусы/версии актуальны на 2024–2026 — стоит перепроверять перед апгрейдами.
- Сравнение Sigma/Cytoscape/vis-network опирается в основном на один блог (medium confidence) — но для масштаба «сотни нод» не критично.
- Производительность React Flow на сотнях **богатых** HTML-нод не измерена → митигируем компактными нодами + рендером полного текста только в drawer.

## Часть 2. Принятые решения (как построено)

Стек и пользовательский флоу описаны в `README.md` и `AGENTS.md`. Здесь — ключевые решения и их обоснование.

### 2.1 Модель ноды (as-built)

```jsonc
{
  "id": "spark-shuffle-01",
  "kind": "question",             // question (теория) | task (практ. задача с кодом)
  "block": "frameworks",          // frameworks | databases | python | platform
  "subblock": "pyspark",          // под-колонка внутри блока (опц.)
  "topic": "distributed-batch",
  "difficulty": "middle",         // base | junior | middle | senior
  "weight": 13,                   // вес темы (для сэмплирования)
  "title": "Shuffle в Spark",     // короткий заголовок карточки
  "tags": ["spark", "optimization"],
  // тело вопрос/ответ — в Markdown; для kind=task: starterCode, rubric
}
```

`Node` — pydantic с `extra="forbid"`: каждый импортируемый файл валидируется, битый frontmatter → внятная
ошибка (паттерн Astro+Zod). Поля `edges`/ветвления **нет** (см. §2.3). Формат frontmatter — в `README.md`.

### 2.3 Что не реализовано (и почему)

- **Рёбра / ветвление графа.** Были спроектированы три измерения ветвления в одной схеме (по теме `topic-jump`, по сложности `difficulty-up/down`, условное `conditional` по `minScore`/`maxScore` — идейная основа из **CAT**, адаптивного подбора следующего вопроса). На практике **отвергнуты**: доска карточек по направлениям × сложности оказалась достаточной и проще в навигации, маршрутизацию интервьюер ведёт сам. Поле `edges` удалено из модели. Рассмотренный prior art: QST (skip-logic, `github.com/bobb34/QST`), Interact (визуальный canvas, `tryinteract.com`), CAT (`arxiv.org/2108.07386`). Формат **json-quiz отвергнут** ещё на исследовании — в нём нет ветвления (`json-quiz.github.io`).
- **pywebview-упаковка.** Опциональный десктоп-режим без браузера; пока запускаем как локальный веб-сервис, упаковку не делали (шов остаётся открытым).
