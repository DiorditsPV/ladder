# SSO и каталоги пользователей

Корпоративный вход — блокирующее требование почти любого enterprise-заказчика: сотрудники
входят своими рабочими учётками, а не заводят отдельный пароль. Тесно связано с
`team-workspace` (аккаунты/роли).

## Системы рынка РФ

| Система | Тип | Протокол/интеграция |
|---|---|---|
| **Active Directory / LDAP** | корпоративный каталог (всё ещё массово) | LDAP, SAML/OIDC через ADFS/Keycloak |
| **Keycloak** | self-hosted IdP (частый выбор импортозамещения) | OIDC, SAML |
| **ALD Pro** (Astra) | каталог для Astra Linux/госсектор | LDAP/Kerberos, OIDC |
| **FreeIPA** | каталог, open-source | LDAP/Kerberos |
| **Yandex ID** | соц/корп вход (Яндекс 360) | OAuth2/OIDC |
| **VK ID** | соц/корп вход | OAuth2/OIDC |
| **Sber ID** | соц вход | OAuth2/OIDC |
| **ЕСИА (Госуслуги)** | для госструктур/B2G | OIDC-совместимый профиль |

## Сценарии ценности
1. **Единый вход (SSO)** через корпоративный IdP — сотрудник уже залогинен.
2. **Провижининг/деактивация.** Пользователи и роли подтягиваются из каталога; уволенный
   автоматически теряет доступ — важный пункт ИБ-аудита заказчика.
3. **Группы → роли.** Группа AD/Keycloak маппится в роль воркспейса (admin/интервьюер).

## Фича-кандидат
- **`sso-ru-identity` (P1).** Корпоративный вход поверх `team-workspace`: OIDC/SAML
  (Keycloak, ADFS, ALD Pro), LDAP-бинд (Active Directory), соц-провайдеры (Yandex ID,
  VK ID). Маппинг групп → роли, опциональный SCIM/LDAP-провижининг.
  _Слои: backend — OIDC/SAML/LDAP-провайдеры за единым интерфейсом аутентификации,
  маппинг групп; фронт — кнопки «Войти через …» и админ-настройка IdP._

## Технические заметки
- **OIDC — базовый протокол.** Yandex ID, VK ID, Keycloak, ADFS, ALD Pro — все умеют OIDC;
  один OIDC-клиент с настраиваемым `issuer`/`client_id` закрывает большинство кейсов.
- **SAML** нужен части enterprise-IdP (наследие) — закладывать как второй протокол.
- **LDAP-бинд** для чистого Active Directory без федерации.
- **on-prem.** В закрытых контурах внешние Yandex/VK ID недоступны — обязательно
  поддержать self-hosted IdP (Keycloak) и LDAP.
- ⚠️ Скоупы/claims конкретных провайдеров — сверить (см. `_verify.md`).
