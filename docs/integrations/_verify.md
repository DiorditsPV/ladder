# Чек-лист проверки перед реализацией интеграции

Данные в этой директории собраны по состоянию знаний и **подлежат сверке** перед началом
работ по каждому коннектору. Российский рынок ПО быстро меняется (ребрендинги, уход
вендоров, новые версии API). Перед реализацией фичи `*-sync` / `*-import` / `*-disks` и т.п.
пройти чек-лист:

## По каждой внешней системе
- [ ] Актуальная **официальная документация API** (адрес, версия, дата).
- [ ] **Метод аутентификации** (OAuth2 scopes / API-ключ / LDAP-бинд / вебхук-токен) и
      процесс получения доступа (нужен ли партнёрский статус / приложение в маркетплейсе).
- [ ] **Лимиты** (rate limits, размеры, квоты) и поведение при их превышении.
- [ ] **Сущности и поля** для маппинга (наш кандидат/сессия/скоркарт ↔ их объекты).
- [ ] **Вебхуки**: какие события, формат, подпись/верификация, гарантии доставки.
- [ ] **Идемпотентность**: как избежать дублей при повторной доставке.
- [ ] **Доступ к ПД**: что отдаёт API по персональным данным, ограничения, согласия (152-ФЗ).
- [ ] **on-prem / закрытый контур**: доступен ли API во внутренней сети заказчика.
- [ ] **Песочница / тестовый стенд** для разработки.
- [ ] **Стабильность вендора**: не уходит ли с рынка, статус в реестре росПО (если важно).

## Системы, требующие особого внимания
- **1С (ЗУП/ERP):** нет единого API — обмен проектируется под конфигурацию заказчика
  (OData-публикация / HTTP-сервисы пишутся на стороне 1С). Согласовать формат до оценки.
- **hh.ru:** доступ к резюме/ПД соискателей регулируется политикой; уточнить условия
  API работодателя.
- **ВКС:** возможности (создание встречи vs запись vs планирование) сильно разнятся между
  Телемост / TrueConf / Контур.Толк / VK Звонки.
- **SSO в закрытом контуре:** внешние Yandex/VK ID недоступны — проверять self-hosted IdP.
