# Интеграции с внешней инфраструктурой (рынок РФ)

> **Назначение.** Стратегическое исследование по интеграциям сервиса «Интервью · граф
> вопросов» с внешними системами, популярными на российском рынке. Цель — чтобы решение
> можно было продавать в российские компании и встраивать в их существующую инфраструктуру
> (СХД/диски, CRM, ERP/HRM, ATS, SSO, мессенджеры, ВКС).
>
> Это **самостоятельная тема платного тира**. Список фич-кандидатов и их приоритеты —
> в конце документа; они также заведены в GitHub Issues отдельным epic-ом
> «Интеграции с внешними системами (РФ)».
>
> ⚠️ **Актуальность данных.** Сведения об API, лимитах и версиях приведены по состоянию знаний
> и подлежат проверке по официальной документации на момент реализации каждой интеграции
> (см. чек-лист в `_verify.md`). Российский рынок ПО быстро меняется (импортозамещение,
> ребрендинги, уход вендоров).

## Почему это критично для продаж в РФ

1. **Никто не покупает «остров».** У компании уже есть ATS, CRM, 1С, корпоративный диск и
   каталог пользователей. Решение без интеграции = двойной ввод данных = его не внедрят.
2. **Импортозамещение.** С 2022 г. рынок ушёл от Google/Microsoft/SAP к Яндекс 360, VK,
   1С, МойОфис, Bitrix24, Astra. Интеграции должны целиться в **российский** стек.
3. **Регуляторика (152-ФЗ, реестр российского ПО).** Для госкомпаний и крупного бизнеса
   это блокирующее требование, а не «приятный бонус» (см. `compliance-rf.md`).
4. **Канал HR-данных замкнут на найме.** Наш сервис — точка в воронке найма; ценность
   возникает, когда результат интервью **бесшовно** уходит дальше (в ATS → в кадровый 1С).

## Технический фундамент: коннектор-платформа

Перед точечными интеграциями нужен общий слой, иначе каждая интеграция превратится в
спагетти. Предлагаемая архитектура (фича `integration-hub`):

- **Реестр коннекторов** — единый интерфейс `Connector` (auth, pull, push, map). Каждая
  внешняя система — плагин.
- **Хранилище секретов/токенов** — OAuth-токены, API-ключи, refresh-логика; шифрование at-rest.
- **Маппинг полей** — настраиваемое соответствие наших сущностей (кандидат, сессия,
  скоркарт, оценка) ↔ полям внешней системы (UI-конструктор маппинга).
- **Диспетчер вебхуков и очередь** — входящие события (новый кандидат в ATS) и исходящие
  (скоркарт готов → push в CRM) через очередь с ретраями и идемпотентностью.
- **Журнал интеграций** — аудит обменов (что, когда, успех/ошибка) для отладки и для
  требований безопасности заказчика.

Это снимает завязку `team-workspace` (облако/Postgres/auth уже есть в paid-беклоге) —
интеграции опираются на него.

## Рекомендуемая последовательность

1. **Волна 1 (фундамент + якорь):** `integration-hub` → `ats-huntflow-sync`. Один сильный
   ATS-коннектор на готовой платформе — это уже продаваемая история.
2. **Волна 2 (enterprise-вход и охват):** `sso-ru-identity` + `hh-jobboards-import` +
   `notify-telegram-vkteams` + `scheduler-page` (+ `calendar-email-sync`). Закрывает вход,
   источник кандидатов, вовлечение и «день интервьюера» (расписание → доска одним кликом).
3. **Волна 3 (глубина процесса):** `storage-ru-disks`, `crm-bitrix-amocrm`, `erp-1c-hrm`,
   `video-vks-ru` — по запросу конкретных сделок.
4. **Параллельно/по требованию гос:** `compliance-rf` (on-prem, рособлака, реестр росПО).
