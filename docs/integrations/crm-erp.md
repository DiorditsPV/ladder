# CRM и ERP / HRM

Две связанные, но разные истории: **CRM** — про воронку и карточку (особенно для
рекрут-агентств), **ERP/HRM** — про передачу нанятого сотрудника в кадровый учёт и зарплату.

## CRM

| Система | Положение | Интеграция |
|---|---|---|
| **Bitrix24** | самый массовый в РФ, SMB→enterprise | REST API + входящие/исходящие вебхуки, OAuth (локальные/тиражные приложения) |
| **amoCRM** | продажи/воронки, популярен | REST API, digital pipeline, вебхуки |
| **Мегаплан** | SMB/средний | REST API |
| **1С:CRM** | внутри 1С-экосистемы | через 1С (OData/HTTP-сервисы) |
| **ELMA365** | BPM+CRM, enterprise | REST API, low-code |

### Сценарии ценности
- **Карточка кандидата = сущность CRM** (лид/контакт/сделка). Для **рекрут-агентств**
  кандидат — это товар: воронка, статусы, выставление клиенту. Результаты интервью и
  бренд-отчёт (`white-label-reports`) прикрепляются к сделке.
- **Авто-задача/уведомление** ответственному при готовности скоркарта.

### Фича-кандидат
- **`crm-bitrix-amocrm` (P2).** Экспорт результата интервью в Bitrix24/amoCRM: создать/
  обновить карточку (контакт/сделка), приложить отчёт, выставить статус/задачу.
  _Слои: backend-коннектор (вебхуки Bitrix24 / REST amoCRM, OAuth), маппинг session↔deal,
  фронт — «отправить в CRM» + статус отправки._

## ERP / HRM (кадры и зарплата)

| Система | Положение | Интеграция |
|---|---|---|
| **1С:Зарплата и управление персоналом (ЗУП)** | стандарт кадрового учёта РФ | OData, HTTP-сервисы, обмен через планы обмена/файлы |
| **1С:ERP**, **1С:Предприятие** | крупный бизнес | OData/HTTP-сервисы |
| **VK HR Tek** | кадровый ЭДО (КЭДО) | REST API |
| **БОСС-Кадровик**, **Галактика ERP** | крупные/госкорпорации | API/интеграционные шины |
| **SAP SuccessFactors** | уходит с рынка, замещается | (наследие) |

### Сценарии ценности
- **Передача нанятого.** Кандидат с решением «hire» → черновик в кадровую систему
  (ФИО, позиция, грейд, итоговая оценка) для оформления. Закрывает процесс «от интервью
  до трудоустройства» — это аргумент для крупных заказчиков.
- **Справочники.** Подтягивать из 1С/HRM структуру подразделений и должностей, чтобы
  привязывать интервью к реальным вакансиям/оргструктуре.

### Фича-кандидат
- **`erp-1c-hrm` (P2).** Обмен с 1С:ЗУП/1С:ERP: исходящий — кандидат с решением hire как
  претендент/событие подбора; входящий — справочники должностей/подразделений.
  _Слои: backend-коннектор 1С (OData/HTTP-сервисы, аутентификация 1С), маппинг сущностей,
  планировщик обмена. Усилия L — 1С обмены требуют согласования формата на стороне заказчика._

## Технические заметки
- **Bitrix24:** проще всего стартовать через входящий вебхук (без публикации приложения);
  для маркетплейса — локальное/тиражное приложение с OAuth.
- **1С:** нет «одного API» — обмен проектируется под конфигурацию заказчика (OData
  включается в публикации, HTTP-сервисы пишутся на стороне 1С). Закладывать адаптер, а не
  «жёсткий» коннектор.
- ⚠️ Всё — сверить по документации конкретной версии/конфигурации (см. `_verify.md`).
