# ATS и job-boards (рекрутинг)

Самая важная категория: наш сервис живёт внутри воронки найма, а ATS — её ось.

## Системы рынка РФ

| Система | Тип | Положение на рынке | Интеграция |
|---|---|---|---|
| **Huntflow** | ATS | де-факто стандарт для IT/среднего бизнеса | публичный REST API + вебхуки, OAuth; хорошая документация |
| **Поток** (VK) | ATS | enterprise, экосистема VK | REST API / вебхуки |
| **Talantix** (hh.ru) | ATS | связка с hh.ru, SMB/средний | API, нативная связь с hh.ru |
| **E-Staff** | ATS | давний игрок, банки/крупные | API / выгрузки (серверная установка) |
| **SkillaZ / Skillaz** | ATS | enterprise, автоматизация | API, вебхуки |
| **FriendWork** | ATS | SMB | REST API |
| **hh.ru** | job-board | главный источник кандидатов в РФ | API работодателя: вакансии, отклики, резюме, негоциации |
| **Avito Работа**, **SuperJob**, **Работа.ру** | job-boards | массовый/синий воротничок | API/выгрузки разной зрелости |

## Сценарии ценности

1. **Импорт кандидата → доска.** Кандидат и вакансия из ATS/job-board попадают в сессию
   интервью без ручного ввода (ФИО, позиция, грейд, резюме во вложении).
2. **Возврат результата → ATS.** Скоркарт, средний балл, рекомендация hire/no-hire и
   ссылка на наш HTML-отчёт пишутся обратно в карточку кандидата ATS.
3. **Смена статуса.** По итогу интервью — автоматический перевод кандидата по этапу
   воронки ATS (например, «Техинтервью пройдено»).
4. **Подбор вопросов под вакансию.** Из текста вакансии (стек, грейд) предлагается трек/
   набор вопросов нашего банка.

## Фичи-кандидаты

- **`ats-huntflow-sync` (P0).** Двусторонняя синхронизация с Huntflow: импорт
  кандидатов/вакансий по вебхуку или pull; обратная запись скоркарта/статуса/ссылки на
  отчёт. Якорная интеграция — закрывает «как это встроится в наш найм».
  _Слои: backend-коннектор (OAuth, вебхуки, маппинг), модель связи session↔external_candidate,
  фронт — кнопка «привязать к кандидату ATS» и индикатор синка._

- **`hh-jobboards-import` (P1).** Импорт вакансий и откликов/резюме из hh.ru (API
  работодателя), задел под Avito Работа/SuperJob. Создаёт сессию из отклика.
  _Слои: backend-коннектор hh.ru (OAuth работодателя), парсер резюме во вложение/заметку._

## Технические заметки

- **Huntflow:** OAuth2, REST, вебхуки на события кандидата/этапа; сущности — applicant,
  vacancy, vacancy_request, статусы. Обратная запись — комментарий/вложение/смена статуса.
- **hh.ru:** OAuth работодателя, лимиты на запросы; резюме доступны в рамках откликов на
  вакансии работодателя (учитывать политику доступа к ПД соискателя).
- **Идемпотентность:** внешние ID кандидата/вакансии хранить у себя, чтобы повторные
  вебхуки не плодили дубли сессий.
- ⚠️ Конкретные эндпоинты, скоупы и лимиты — сверить по актуальной документации вендоров
  (см. `_verify.md`).
