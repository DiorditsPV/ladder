# Закрытие v1: настройка интервью, итог сессии, гостевая ссылка — дизайн и план

Дата: 2026-09-03 · статус: план утверждён владельцем («приступаем»), инкременты идут по очереди ·
контекст: `~/dev/docs/lichnoe/interview-graph/2026-09-03-v1-gap-analysis.md`.

## Зачем

Демонстрационный flow «Data Engineer → матрица → выбрать Junior / Spark / Airflow → начать интервью →
оценить 5–7 вопросов → отчёт» рвётся посередине: фильтры на матрице не становятся набором вопросов,
интервью стартует с главной без выбранной области, у сессии нет итога, а подключиться можно только
с аккаунтом. Три инкремента закрывают частично сделанные экраны: Настройка интервью и Live-интервью
по набору, Сессии и Отчёт с итогом, Подключение по ссылке.

## Инкремент 1 — Настройка интервью и набор вопросов сессии

### Модель
- `sessions.plan` (TEXT, JSON, NULL у старых сессий):
  `{"mode": "manual" | "auto", "blocks": [...], "subblocks": {"<block>": [...]}, "difficulties": [...],
   "count": N, "order": ["<node id>", ...]}`. `order` — итоговый упорядоченный набор; всё остальное —
  параметры, по которым он собран (для отчёта и повторного интервью).
- Сессия без `plan` ведёт себя как сегодня (вся матрица).

### API
- `POST /api/sessions` принимает `plan?: {mode, blocks?, subblocks?, difficulties?, count?, nodeIds?, seed?}`:
  - `manual` — `order` = `nodeIds` (должны принадлежать пулу, порядок сохраняется), либо, если
    `nodeIds` нет, все подходящие под фильтры в порядке матрицы (блок → под-колонка → сложность → id);
  - `auto` — сэмплер `build_interview` по нодам, отфильтрованным блоками/под-колонками/уровнями,
    `count` (по умолчанию 7), веса блоков пула, `seed`.
  - Пустой набор → 422 («нет вопросов под выбранные условия»).
- `GET /api/sessions/{id}` возвращает `plan`; `GET /api/sessions` — `plan_count` (длина `order`, NULL без плана).
- `sampler.build_interview` получает `blocks`/`subblocks` как фильтр (сегодня — только `difficulties`).

### Экран «Настройка интервью» (`#/setup/<pool>?blocks=…&subs=…&diffs=…`)
Секции: Кандидат (существующий или новый: имя, позиция, грейд), Разделы (чекбоксы разделов и
под-колонок, по умолчанию все, префилл из query), Уровни (base…senior, по умолчанию все), Режим
(«Все подходящие в порядке матрицы» / «Автоподбор N вопросов по весам», N по умолчанию 7), строка
«Подходит N вопросов» (клиентский подсчёт по `GET /api/graph`). Кнопки «Отмена» / «Начать интервью →».
Точки входа: карточка направления на главной (вместо встроенной формы) и «Начать интервью →» на
доске (передаёт текущие фильтры доски в query).

### Доска в сессии с планом
Агенда и «Дальше» идут по `plan.order`; HUD показывает «3 / 7»; вопросы вне плана затемнены и не
выбираются (как отфильтрованные); прогресс сессии — «оценено X / N» по плану. Стартовый вопрос —
первый в плане. Без плана — как сегодня.

### Проверка
pytest: план manual/auto, фильтры, 422 на пустой набор, старые сессии без плана; smoke: старт через
экран настройки с автоподбором 5 вопросов → агенда 5 пунктов, HUD «/ 5», вопрос вне плана затемнён.

## Инкремент 2 — Итог сессии (Сессии, Отчёт)
- `sessions.status` (`active` | `finished`), `decision` (`hire` | `no_hire` | `hold`, NULL), `summary` (TEXT).
- `POST /api/sessions/{id}/finish {decision, summary}`; повторный вызов правит итог.
- Доска: «Завершить» открывает форму итога (решение + комментарий) → статус finished, отчёт.
- Страница Сессии: статус, решение; фильтр «идущие / завершённые».
- Отчёт: блок «Итог» (решение, комментарий), «Сильные / слабые разделы» по средним оценкам плана.

## Инкремент 3 — Подключение по ссылке
- `session_invites` (token, session_id, role viewer|member, created_at); `POST /api/sessions/{id}/invite`.
- Маршрут `#/join/<token>`: гостевая auth-сессия с ролью из приглашения, ограниченная одной сессией;
  доска открывается сразу в сессии. Кнопка «Ссылка для коллеги» в toolbar сессии.
