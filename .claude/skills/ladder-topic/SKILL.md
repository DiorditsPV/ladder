# ladder-topic

Тема → каркас (колонки × уровни под саму тему) → карточки с покрытием каждой ячейки → `content/<slug>/` → sync → доска.

## Когда применять
- «Хочу разобрать тему X» / «заведи направление X» / «пересобери направление X со своими уровнями».
- Дополнить существующую тему до полного покрытия («в Kafka пустые ячейки — добей»).
- НЕ применять для одного-двух вопросов в существующий пул — это `interview-ideas`.

## Вызов
`/ladder-topic <тема> [--lang ru|en] [--per-cell N] [--fresh] [--pool <slug>] [--yes]`
По умолчанию `ru`, `N=2`, slug — транслит темы (`Apache Kafka` → `apache-kafka`), без `--fresh` — дополнение.
`--yes` — не ждать подтверждения каркаса (только когда владелец явно сказал не спрашивать).

## Процесс

### 1. Каркас — единственный гейт
Предложи таблицу «колонки × уровни» и **остановись, пока владелец не подтвердит** (кроме `--yes`):
каркас дешевле переделать, чем 60 карточек.
- **Колонки** — 3–6 областей темы, по которым её реально учат и спрашивают; у широкой области — под-колонки
  (`subblocks`), у узкой — нет. Подписи на языке `--lang`.
- **Уровни** — 4–6 ступеней освоения **этой** темы, по возрастанию, с подписями, из которых видно, что человек умеет
  на ступени. Для Kafka: «Понятия → Конфигурация → Эксплуатация → Внутренности → Проектирование». Для методологии
  (аналитик, менеджмент): «Понятия → Практика → Проектирование → Экспертиза».
  Не бери лестницу «beginner / intermediate / advanced» и не junior/middle/senior — они ничего не говорят о теме.
- `id` колонок и уровней — короткие латинские slug'и; тема целиком — `pool.id` = slug.

### 2. Карточки
На каждую ячейку колонка × уровень — не меньше `N` карточек; распределяй по под-колонкам, если они есть.
Правила карточки:
- **Вопрос** — одна вещь, на которую можно ответить за 3–5 минут вслух; без «расскажите всё о…».
- **Ответ** — 400–1500 знаков (скрипт предупредит о выходе за ориентир): сначала суть, потом механика, потом пример на реальном стеке/ситуации; для уровней
  «Проектирование/Экспертиза» — компромиссы и когда так делать не надо. Не пересказывай вопрос.
- Внутри ячейки карточки не повторяют друг друга по смыслу; уровень задаёт глубину, а не тему.
- **Самопроверка перед записью** (её не делает скрипт — только ты): (1) уровень должен быть виден из самого
  **вопроса**: «что такое X» не бывает `expert`, даже если ответ заканчивается компромиссами; для верхних уровней
  вопрос — кейс или задача выбора; (2) перечитай соседей по под-колонке и по уровню — одинаковый пример или
  одинаковая механика в двух карточках = дубль, даже если формулировки разные; (3) ответ длиннее 1500 знаков
  чаще всего означает две карточки в одной — раздели.
- `tags` — 1–3 из 17 сквозных концептов (architecture, orchestration, optimization, partitioning, deployment,
  storage, streaming, consistency, data-modeling, quality, distributed, sql, monitoring, memory, file-formats,
  domain, concurrency). Словарь дата-инженерный: если тема вне него (аналитика, менеджмент, фронт) — предложи в
  каркасе 3–6 **своих тегов темы** (slug латиницей: `requirements`, `contracts`, `process`) и положи их в `pool.tags`;
  скрипт принимает 17 ∪ `pool.tags`. Названия технологий тегами не бывают.
- **Ни одна строка вопроса или ответа не начинается с `#`** — ни заголовок, ни комментарий в bash-блоке:
  импортёр режет тело по строкам-заголовкам. Подзаголовки — жирным, комментарии в коде — в конце строки.
- `id` = `<slug>-<колонка>-NN` — скрипт проверяет и префикс, и колонку в середине; NN — двузначный номер, при
  дополнении продолжает нумерацию колонки. `title` — 3–7 слов (скрипт отвергает короче 2 и длиннее 8), `topic` внутри колонки не повторяется (скрипт предупредит),
  `topic` — короткий slug подтемы, `kind: question` (задачи `task` — только если тема про код и есть эталон).

### 3. Запись и покрытие — скриптом, не руками
Собери JSON по контракту (ниже) в scratch-файл — 40+ карточек удобнее собирать python-скриптом по колонкам
(список dict'ов на колонку → `json.dump`), а не печатать JSON руками. Сначала `--check` (валидация и матрица; ничего не пишет и не сносит даже с `--fresh`), потом запись; из корня репозитория:
```bash
. backend/.venv/bin/activate
python3 .claude/skills/ladder-topic/write_topic.py /tmp/topic.json --per-cell N --check
python3 .claude/skills/ladder-topic/write_topic.py /tmp/topic.json --per-cell N [--fresh] --sync --api http://localhost:8000
```
Скрипт валидирует (теги, уровни, префикс id, subblock), пишет `pool.yaml` (веса блоков ∝ числу карточек) и карточки
в нормализованном формате, печатает матрицу, покрытие под-колонок и ячейки с `!` (тоньше N), делает `POST /api/pools/sync` и проверяет
`/api/graph` → 0 ошибок. Выход `2` = есть тонкие ячейки: допиши карточки в них и запусти снова **без** `--fresh`
(занятые id пропускаются, новые дописываются). `--api` — адрес сервера с новым кодом (dev — `:8001`). **Контейнер на `:8000` не видит `content/` с диска** — он запечён в образ:
после записи либо `docker compose up -d --build`, либо `--sync --api http://localhost:8001` на `./run.sh dev`.
Правка текста существующей карточки — только через `--fresh` (без него занятые id пропускаются): выверяй на `--check`, пиши один раз.
Файлы в `content/` руками не пиши и Read-инструментом не читай (кэш врёт) — `cat`/`grep`/`/api/graph`.

### 4. Проверка и отчёт
`cd backend && pytest -q tests/test_app.py -k imports` (каждый пул импортируется: ≥10 нод, title, 1–3 тега).
Отчёт владельцу: матрица покрытия, число карточек, ссылка `#/board/<slug>`, что подрезал/чего не хватило.

## Контракт JSON для write_topic.py
```json
{"pool": {"id": "kafka", "label": "Apache Kafka", "description": "…",
          "blocks": [{"id": "core", "label": "Ядро", "subblocks": [{"id": "log", "label": "Лог и партиции"}]},
                     {"id": "ops", "label": "Эксплуатация"}],
          "levels": [{"id": "concepts", "label": "Понятия"}, {"id": "config", "label": "Конфигурация"}]},
 "cards": [{"id": "kafka-core-01", "block": "core", "subblock": "log", "difficulty": "concepts",
            "title": "Топик, партиция, offset", "topic": "log-basics", "tags": ["streaming", "partitioning"],
            "question": "…", "answer": "…"}]}
```
`color` у блоков не обязателен (палитра по порядку), `weight` карточек — 1; `pool.tags` (необязательно) — свои теги
темы сверх 17 концептов. Креды для `--sync` — `INTERVIEW_OWNER_EMAIL`/`INTERVIEW_OWNER_PASSWORD` (дефолты dev-сервера).

## Пересборка и дополнение
- `--fresh` сносит `content/<slug>/` целиком — старые карточки уходят в git-историю, а в БД прячутся sync'ом
  (оценки завершённых сессий на них остаются видны в отчёте). Перед `--fresh` спроси, если не `--yes`.
- Без `--fresh` — дополнение: `pool.yaml` перезаписывается из JSON (уровни/колонки должны совпадать с существующими
  или расширять их), карточки с занятыми id пропускаются.
- `data-engineer` и `data-engineer-x5` — не пересобирать никогда.

## Типичные ошибки (из прогона без скилла)
| Ошибка                                                          | Чем плоха                                            | Как правильно                                  |
|-----------------------------------------------------------------|------------------------------------------------------|------------------------------------------------|
| Уровни `foundation/intermediate/advanced`, подписи по-английски | ряд на доске ничего не говорит о теме                | ступени освоения темы, подписи на `--lang`     |
| `# comment` в bash-блоке ответа                                 | импортёр считает строку заголовком и режет ответ     | комментарий в конце строки или `//`            |
| Карточки написаны руками в `content/`                           | формат не нормализован, покрытие не проверено        | JSON → `write_topic.py`                        |
| Публикация через `POST /api/import`                             | грузит по одному файлу и не обновляет конфиг пула    | `--sync` (или «Обновить из файлов» на главной) |
| Теги только из 17 концептов для темы вне DE                     | всё схлопывается в `quality`/`architecture`/`domain` | `pool.tags` со своими тегами темы              |
| Одна карточка на ячейку «для начала»                            | ряд из одной карточки — не разбор, а заголовок       | `--per-cell 2`, тонкие ячейки — добить         |
