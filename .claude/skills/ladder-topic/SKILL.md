# Создание доски по теме

Сначала прочитай [общий стандарт качества](references/content-quality.md).
Он обязателен для отбора материала, последовательности, терминов, источников и оформления.
Продукт — самоподготовка; по умолчанию вопросы уровня собеседования, уровни `base/junior/middle/senior`.

## Подготовить содержание

1. Определи границы и размер по запросу, изучи первоисточники, составь карту основных механизмов.
   Отсей второстепенное до написания вопросов. Если важная неопределённость мешает работе, уточни её;
   при ясной задаче продолжай самостоятельно в уже разрешённом объёме.
2. Выдели колонки и при необходимости под-колонки, затем содержательные `topic` и уровни.
   Покажи краткий каркас и маршрут изучения. Не навязывай количество колонок, тем или карточек на ячейку.
3. Построй зависимости понятий. Напиши вопросы от основ к взаимодействиям и выбору, без нумерации.
   Один `topic` может включать несколько разных вопросов; одна колонка — несколько `topic`.
4. Напиши ответы на основе прочитанных источников, сопоставь ключевые тезисы с разделами документов.
   Выдели определения, добавь полезные сравнения, код и пояснения результатов.
5. Проведи редакционное ревью всей доски по общему стандарту, включая порядок в реальной раскладке.

## Выбрать место записи

Установи **точный адрес сервиса и ID направления** из запроса и состояния окружения.
Не считай localhost:8000, другой локальный порт и production одной доской.

- Для доски в работающем сервисе используй подключённый Ladder MCP, если доступен, либо его API.
  Сначала прочитай актуальные возможности инструментов и существующее направление; затем выполни
  создание/изменение в разрешённом объёме. Не полагайся на запомненные имена инструментов и схемы.
  Готовый JSON темы заносит `write_topic.py --upload` (адрес и вход — `LADDER_URL`, `LADDER_EMAIL`,
  `LADDER_PASSWORD`): нет направления — создаёт его с id колонок и уровней из JSON; есть — дописывает
  недостающие колонки, под-колонки и уровни, ничего не удаляя.
- Контент живёт в базе сервиса. В `content/` репозитория — только пресеты (`data-engineer`,
  `system-analyst` и их `-en`); новые направления туда не пиши, деплой их не доставит.
  Файлы пресетов читаются через `cat`/`rg`, правятся через `python-frontmatter` из `backend/.venv`
  или `write_topic.py --files`.
- `sync` читает файлы **на стороне сервера**. Локальная запись не доставляет их на удалённый сервер
  или внутрь образа контейнера. Старт сервера и `POST /api/pools/sync` без параметров только засевают
  недостающее; обновить пресет из файлов — `--files --sync` (это `POST /api/pools/sync?pool=<id>&update=true`,
  только этот пул; вручную сначала с `dry_run=true`).

Сохраняй ID существующих карточек при переформулировке. `--fresh` (только с `--files`) удаляет каталог:
используй только в пределах явно разрешённой полной замены. Обычный режим скрипта дополняет, а занятые ID
пропускает; повторный запуск существующую карточку не обновит — для правки `--upload --overwrite`
(обновит карточки из JSON), MCP/API или frontmatter пресета.

## Формат и локальный помощник

Таксономия берётся из `pool.yaml`; не подменяй уровни и колонки существующего пула.
Новые уровни — 2–8, по умолчанию четыре стандартных. Теги — 1–3 из 17 концептов текущего `AGENTS.md`,
без названий технологий и расширений `pool.tags`. Поля `edges`/`sources` не добавляй.

`write_topic.py` принимает JSON следующей формы (значения здесь — пример схемы, не готовая карточка):

```json
{
  "pool": {
    "id": "example", "label": "Тема", "description": "Границы темы",
    "blocks": [{"id": "core", "label": "Основы"}],
    "levels": [
      {"id": "base", "label": "Base"}, {"id": "junior", "label": "Junior"},
      {"id": "middle", "label": "Middle"}, {"id": "senior", "label": "Senior"}
    ]
  },
  "cards": [{
    "id": "example-core-01", "block": "core", "difficulty": "base",
    "title": "Короткий заголовок", "topic": "Содержательная тема", "tags": ["architecture"],
    "question": "Формулировка вопроса", "answer": "Ответ с Markdown и ссылками"
  }]
}
```

У блока возможны `color`, `subblocks: [{id, label}]`; тогда у карточки укажи `subblock`.
Помощник предназначен для вопросов; задачи со `starterCode`/`rubric` оформляй напрямую по модели Node
(`--upload` передаст эти поля, если они есть в карточке JSON).

```bash
backend/.venv/bin/python .claude/skills/ladder-topic/write_topic.py /tmp/topic.json --check
LADDER_URL=<адрес сервиса> LADDER_EMAIL=<почта> LADDER_PASSWORD=<пароль> \
  backend/.venv/bin/python .claude/skills/ladder-topic/write_topic.py /tmp/topic.json --upload
```

Режим обязателен и один: `--check` ничего не пишет, `--upload` заносит в сервис (основной путь), `--files` пишет
в `content/` — только для пресетов. Локальный контейнер: `LADDER_URL=http://localhost:8000 LADDER_EMAIL=admin
LADDER_PASSWORD=admin`.

По умолчанию матрица информационная. `--per-cell N` используй только при явном требовании пользователя
о минимуме; код 2 означает нарушение этой заданной квоты, а не плохое содержательное покрытие.
Длина ответа не проверяется числом знаков. Веса помощник вычисляет из количества карточек —
это описание распределения, не независимое доказательство важности тем.
Для `--upload` и `--files --sync` передай проверенный базовый URL (`LADDER_URL` или `--api`), без суффикса `/api`.

После записи используй [interview-verify](../interview-verify/SKILL.md).
Прочитай результат из того же сервиса, сверь карточки и оформление, дай пользователю точную ссылку.
Локальную запись и публикацию сообщай как разные фактически выполненные действия.
