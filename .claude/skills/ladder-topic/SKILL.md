# ladder-topic

Тема → каркас (колонки × уровни сложности) → карточки с лесенкой в каждой под-колонке → JSON → `--check` →
`--upload` в сервис → доска. Контент живёт в базе сервиса: в репозитории (`content/`) только пресеты
data-engineer и system-analyst (spec 2026-09-11-content-in-db).

## Когда применять
- «Хочу разобрать тему X» / «заведи направление X» / «пересобери направление X».
- Дополнить существующую тему до полного покрытия («в Kafka пустые ячейки — добей»).
- НЕ применять для одного-двух вопросов — это MCP `create_question` или `interview-ideas`.

## Вызов
`/ladder-topic <тема> [--lang ru|en] [--per-cell N] [--overwrite] [--pool <slug>] [--yes]`
По умолчанию `ru`, `N=2`, slug — транслит темы (`Apache Kafka` → `apache-kafka`); без `--overwrite` — дополнение
(занятые id пропускаются). `--yes` — не ждать подтверждения каркаса (только когда владелец явно сказал не спрашивать).

## Процесс

### 1. Каркас — единственный гейт
Предложи таблицу «колонки × уровни» и **остановись, пока владелец не подтвердит** (кроме `--yes`):
каркас дешевле переделать, чем 60 карточек.
- **Колонки** — 3–6 областей темы, по которым её реально учат и спрашивают; у широкой области — под-колонки
  (`subblocks`), у узкой — нет. Подписи на языке `--lang`.
- **Уровни — одна шкала сложности**: сверху проще, вниз строго сложнее, в каждой колонке и под-колонке. По умолчанию
  4 ступени «Основы → Практика → Продвинутый → Эксперт». Вид вопроса (настройка, отладка, устройство, выбор) —
  свойство карточки, а не ряд: лестница «Понятия → Настройка → Диагностика → Внутренности → Проектирование» —
  это виды знания, так не делать.
- `id` колонок и уровней — короткие латинские slug'и; тема целиком — `pool.id` = slug.

### 2. Карточки
**Каждая под-колонка (колонка без под-колонок) — лесенка без дыр**: первая карточка на верхнем уровне — «что это и
зачем», каждая следующая ниже — сложнее. Не меньше `N` карточек на ячейку колонка × уровень, и у каждой
под-колонки есть карточка первой ступени.
Правила карточки:
- **Вопрос — прямой вопрос о сути**, понятный без контекста и отвечаемый за 3–5 минут вслух: «Что такое shuffle и
  почему он дорогой?», «Как уменьшить shuffle в джобе?». Без мини-кейсов с выдуманными цифрами, таблицами и
  цепочками условий; кейс допустим, только если проблема в нём поставлена полностью и коротко. Без «расскажите всё о…».
- **Ответ** — 400–1500 знаков (скрипт предупредит): сначала ответ на вопрос, потом механика, потом короткий пример
  (иллюстрация, не история); на нижних уровнях — компромиссы и когда так делать не надо. Не пересказывай вопрос.
- Уровень задаёт глубину, а не тему: соседи по ячейке не повторяют друг друга по смыслу.
- **Самопроверка перед записью** (её не делает скрипт — только ты): (1) сложность растёт вниз в каждой под-колонке,
  первая ступень есть, пропусков нет; «что такое X» не бывает на нижнем уровне; (2) перечитай соседей по
  под-колонке — одинаковый пример или одинаковая механика в двух карточках = дубль; (3) ответ длиннее 1500 знаков
  чаще всего — две карточки в одной, раздели.
- `tags` — 1–3 из 17 сквозных концептов (architecture, orchestration, optimization, partitioning, deployment,
  storage, streaming, consistency, data-modeling, quality, distributed, sql, monitoring, memory, file-formats,
  domain, concurrency; словарь отдаёт и MCP `list_tags`). Если тема вне дата-инженерии — предложи в каркасе 3–6
  **своих тегов темы** (slug латиницей: `requirements`, `contracts`, `process`) и положи их в `pool.tags`;
  скрипт принимает 17 ∪ `pool.tags`. Названия технологий тегами не бывают.
- **Ни одна строка вопроса или ответа не начинается с `#`** — ни заголовок, ни комментарий в bash-блоке.
  Подзаголовки — жирным, комментарии в коде — в конце строки.
- `id` = `<slug>-<колонка>-NN` — скрипт проверяет префикс и колонку; NN — двузначный номер, при дополнении
  продолжает нумерацию колонки. `title` — 3–7 слов, `topic` — короткий slug подтемы (внутри колонки не
  повторяется), `kind: question` (задачи `task` — только если тема про код и есть эталон).

### 3. Запись — скриптом, в сервис
Собери JSON по контракту (ниже) в scratch-файл — 40+ карточек удобнее собирать python-скриптом по колонкам
(список dict'ов на колонку → `json.dump`). Сначала `--check`, потом `--upload`; из корня репозитория:
```bash
. backend/.venv/bin/activate
python3 .claude/skills/ladder-topic/write_topic.py /tmp/topic.json --per-cell N --check
LADDER_URL=https://ladder.paveldiordits.site LADDER_EMAIL=… LADDER_PASSWORD=… \
  python3 .claude/skills/ladder-topic/write_topic.py /tmp/topic.json --per-cell N --upload
```
`--upload`: нет направления — создаёт его с id колонок и уровней из JSON; есть — дописывает недостающие колонки,
под-колонки и уровни (ничего не удаляет). Карточки создаются с явными id: занятый id пропускается, с `--overwrite`
— обновляется текстом из JSON. Печатает матрицу покрытия по данным сервера; выход `2` — есть тонкие ячейки: допиши
карточки и запусти снова (новые id добавятся). Креды — аккаунт с правом правки (member/owner); для локального
контейнера — `LADDER_URL=http://localhost:8000 LADDER_EMAIL=admin LADDER_PASSWORD=admin`.
В `content/` новые направления не пиши: там только пресеты (см. ниже).

### 4. Проверка и отчёт
Матрицу после `--upload` проверь глазами: у каждой под-колонки есть первая ступень, пропусков нет. Точечные правки
и перестройка структуры — инструментами MCP (`update_question`, `add_level`, `delete_column` с
`move_questions_to` и т.п.). Отчёт владельцу: матрица покрытия, число карточек, ссылка `#/board/<slug>`, что
подрезал и чего не хватило.

## Контракт JSON для write_topic.py
```json
{"pool": {"id": "kafka", "label": "Apache Kafka", "description": "…",
          "blocks": [{"id": "core", "label": "Ядро", "subblocks": [{"id": "log", "label": "Лог и партиции"}]},
                     {"id": "ops", "label": "Эксплуатация"}],
          "levels": [{"id": "basics", "label": "Основы"}, {"id": "practice", "label": "Практика"},
                     {"id": "advanced", "label": "Продвинутый"}, {"id": "expert", "label": "Эксперт"}]},
 "cards": [{"id": "kafka-core-01", "block": "core", "subblock": "log", "difficulty": "basics",
            "title": "Топик, партиция, offset", "topic": "log-basics", "tags": ["streaming", "partitioning"],
            "question": "…", "answer": "…"}]}
```
`color` у блоков не обязателен (палитра по порядку), `weight` карточек — 1; `pool.tags` (необязательно) — свои теги
темы сверх 17 концептов.

## Дополнение, правка, пресеты
- Дополнение — тот же JSON с новыми карточками и `--upload`: занятые id пропускаются, новые добавляются.
- Правка текстов — `--upload --overwrite` (обновит карточки из JSON) или MCP `update_question` для точечных правок.
- Удаление и перестройка колонок/уровней — через MCP; удаление с вопросами — только с `confirm=true` или после
  `move_questions_to`.
- **Пресеты** (`content/data-engineer`, `content/system-analyst` и их `-en`) правятся в репозитории: `--files`
  пишет файлы, `--files --sync` — явное обновление пресета на сервере (update из файлов, только этого пула). Деплой
  сам по себе пресеты не перезаписывает — синхронизация при старте только засевает недостающее.
- `data-engineer` не пересобирать никогда.

## Типичные ошибки
| Ошибка                                        | Чем плоха                                             | Как правильно                                      |
|-----------------------------------------------|-------------------------------------------------------|----------------------------------------------------|
| Ряды «Понятия → Настройка → Диагностика → …»  | это виды знания, а не сложность; под-колонки без азов | одна шкала сложности, лесенка в каждой под-колонке |
| Вопрос-кейс с выдуманными цифрами и условиями | проблема не поставлена, ответ решает непонятно что    | прямой вопрос о сути                               |
| `# comment` в bash-блоке ответа               | импортёр считает строку заголовком и режет ответ      | комментарий в конце строки или `//`                |
| Новое направление записано в `content/`       | в репозитории только пресеты; деплой его не обновит   | JSON → `write_topic.py --upload`                   |
| Теги только из 17 концептов для темы вне DE   | всё схлопывается в `quality`/`architecture`/`domain`  | `pool.tags` со своими тегами темы                  |
| Одна карточка на ячейку «для начала»          | ряд из одной карточки — не разбор, а заголовок        | `--per-cell 2`, тонкие ячейки — добить             |
