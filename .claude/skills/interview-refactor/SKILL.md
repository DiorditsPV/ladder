# Скилл: рефакторинг вопросов (сложность · актуальность · подача)

Проект: сервис интервью «граф вопросов». Вопросы — в `content/<block>/*.md|*.json`.

## Критично (грабли проекта)
- Ground truth — через `cat`/`grep`/`/api/graph`, **не Read** (кэш устаревает).
- Правки — через `python-frontmatter` (`backend/.venv`), нормализованный формат
  (`frontmatter.dumps(post)+"\n"`). Поля `edges` нет — не добавляй.
- Теги — только из 17 сквозных концептов, 1–3 на ноду (см. interview-ideas). Тех-имена в теги не возвращать.
- После правок — **interview-verify**. Переименование `id` = переименуй файл и поправь ссылку в `Q_IDEAS.txt`.

## Процедура

### Шаг 1. Снять инвентарь
```bash
python3 .claude/skills/interview-refactor/inventory.py
```
Скрипт (stdlib, нужен сервер на :8000) печатает все ноды по группам block/subblock:
`difficulty · kind · id · [tags] · title`. Полный текст конкретной ноды — `cat content/<block>/<id>.md`.

### Шаг 2. Оценить по трём осям (выдать список находок ДО правок)
1. **Сложность.** Соответствует ли `difficulty` глубине вопроса?
   - base = «как устроено / обзор» (архитектура, термины);
   - junior = базовое применение; middle = практические нюансы/оптимизация; senior = trade-offs, масштаб, редкие кейсы.
   Помечай завышенные/заниженные и предлагай новый уровень. Следи, чтобы у колонки была разумная лесенка base→senior.
2. **Актуальность.** Встречается ли реально на дата-инженерных интервью по стеку команды (Airflow/Spark/
   Trino/ClickHouse/Postgres/Kafka/HDFS/S3)? Кандидаты на удаление/деприоритет: слишком узкие, нишевые,
   устаревшие, дублирующие другую ноду. Дубли — предложить merge.
3. **Подача.** Заголовок (`title`) короткий и точный? Вопрос не перегружен (одна тема на ноду)? Ответ
   конкретен и структурен? Не лучше ли разбить «2-в-1» на две ноды или объединить близкие? Корректны ли
   `subblock`/`topic`/`tags`?

### Шаг 3. Согласовать
Покажи находки таблицей: `id · ось · проблема · предлагаемое действие (новый difficulty / reword / split /
merge / move / drop)`. Действия с потерей (удаление, объединение) — подтверждай у пользователя.
Безопасные (difficulty, теги, заголовок, формулировка) — можно применять сразу, сообщив об этом.

### Шаг 4. Применить
- difficulty/tags/title/subblock/topic — правкой frontmatter через `python-frontmatter`.
- reword — правка тела (`## Вопрос`/`## Ответ`), не начинать строки с `#` вне кода.
- split — создать новую ноду (см. interview-ideas) + обновить исходную; новые id по схеме соседей.
- merge/drop — удалить файл(ы), обновить `Q_IDEAS.txt` (убрать `[x]`-строки удалённых id; при merge —
  оставить одну строку).
- move — сменить `block`/`subblock` (и при необходимости `id`/файл) согласно `PREFERRED_SUB` в `layout.ts`.

### Шаг 5. Проверить
Прогнать **interview-verify** (import 0 ошибок, pytest, build, smoke). Затем коротко отчитаться: что
изменено и почему.

## Заметки
- Баланс тем (сколько вопросов на блок) — отдельный скилл **interview-balance**.
- Если рефактор подсветил пробел («нет senior по X») — не выдумывай ноду молча, а заведи идею в `Q_IDEAS.txt`
  (скилл interview-ideas) либо предложи сгенерировать.
