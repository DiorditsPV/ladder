# Ревью существующих вопросов

Прочитай [общий стандарт качества](../ladder-topic/references/content-quality.md).
Работай с доской самоподготовки, её темой и согласованной глубиной; не навязывай стек другой команды.

## Порядок ревью

1. Установи точный сервис/ID пула или каталог контента. Прочитай таксономию и полные вопросы/ответы.
   `inventory.py` даёт сводку, но не заменяет чтения содержимого. Для доступного локального API:
   `API_URL=<адрес-с-/api> POOL=<id> python3 .claude/skills/interview-refactor/inventory.py`.
   Для закрытого направления используй авторизованный MCP/API, а не анонимную выдачу демо.
2. Восстанови карту темы: основные механизмы, связи, предпосылки, существенные ограничения.
   Сопоставь её с первоисточниками и доской. Отметь необходимое, полезное углубление и лишнее.
3. Проверь каждую карточку по осям ниже и кратко изложи находки до применения правок.

| Ось | Что проверить |
| --- | --- |
| Существенность | Что человек не поймёт без вопроса; не случайный ли это узкий случай, UI-деталь или дубль |
| Последовательность | Где введены необходимые понятия, нет ли ссылок вперёд на необъяснённые механизмы |
| Глубина | Уровень виден в вопросе; senior проверяет важные компромиссы, а не редкость |
| Терминология | Принятые названия, выделенные определения, точное различение близких понятий |
| Доказательность | Каждый ключевой тезис подтверждён прочитанным разделом; версии, условия и выводы обозначены |
| Подача | Одна связная мысль, прямой достаточный ответ, полезные примеры и читаемое оформление |

Для находок используй таблицу `ID → проблема → основание → действие`.
Для сложных ответов добавь соответствие `утверждение → источник/раздел → подтверждение/ограничение`.
Если исторический источник неизвестен, скажи это и укажи, чем проверена новая редакция.

## Применить и проверить

Выполняй уже разрешённое редактирование без повторного согласования. Если пользователь просил только
ревью, оставь конкретные предложения. При неразрешённой потере содержимого/прогресса сначала подготовь
конкретное объединение или удаление для согласования; разрешённую часть работы доведи до результата.

- Сохраняй ID при переформулировке и переносе, насколько позволяет модель: к ним привязан прогресс.
- Файлы читай через `cat`/`rg`; Markdown правь через `python-frontmatter`:
  `path.write_text(frontmatter.dumps(post) + "\n", encoding="utf-8")`.
- Колонки, под-колонки и уровни бери из пула; теги — из 17 концептов `AGENTS.md`, 1–3 на карточку.
- При разрешённом split/merge/drop обнови затронутые ссылки реестра `Q_IDEAS.txt`, не теряя другие идеи.
  Удаление seed-карточки в UI и удаление файла имеют разную семантику — см. `AGENTS.md`.
- Разрыв содержания восполняй в пределах задачи; отсутствие senior в ячейке само по себе не требует вопроса.

Примени [interview-verify](../interview-verify/SKILL.md), перечитай итог из фактического места записи.
В отчёте раздели исправленные проблемы, оставшиеся фактические неопределённости и выполненные проверки.
