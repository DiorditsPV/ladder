# Идеи и их реализация

Прочитай [общий стандарт качества](../ladder-topic/references/content-quality.md).
Идея должна закрывать существенную потребность в понимании темы, а не увеличивать количество карточек.
Уточни пул из контекста; прочитай его таксономию, соседние карточки и `Q_IDEAS.txt` через `cat`/`rg`.
Не подставляй автоматически колонки data-engineer или стек X5 для другой темы.

## Добавить или развернуть

Перед добавлением проверь дубли, роль идеи в карте темы и уже раскрытые предпосылки.
Добавь `- [ ] <формулировка>` в подходящую группу `Q_IDEAS.txt`; если группы нет, создай
`Название (block/subblock) — идеи:`. Разворачивая идею, уточни центральный механизм и глубину,
сохраняя одну связную мысль. Не дроби её на пустые микровопросы.
В этих режимах готовые карточки не создавай: это отдельное действие «реализовать».

## Реализовать выбранные идеи

1. Проверь место в карте темы и последовательность: основные понятия должны быть раскрыты раньше
   либо кратко введены в этой карточке. Отсей маловажные идеи с объяснением причины.
2. Прочитай первоисточники, сопоставь ключевые утверждения с разделами. По ним напиши вопрос и ответ,
   выдели определения и добавь пример, если он объясняет механизм. Не копируй слабую подачу соседей.
3. Выбери `id`, `block`, `subblock`, `topic`, `difficulty`, `weight`, `title`, `tags` по модели и пулу.
   Новые ID должны быть уникальны; заголовки и вопросы без нумерации. Стандартные уровни —
   `base/junior/middle/senior`, но сохраняй заданные пулом. Теги — 1–3 из 17 концептов `AGENTS.md`.
4. Для пресета (`data-engineer`, `system-analyst` и их `-en`) создай `content/<pool>/<block>/<id>.md` через
   `python-frontmatter` либо JSON по схеме Node. Остальные направления живут в базе сервиса: карточку
   создай через MCP `create_question` или `POST /api/nodes` — файл в `content/` до них не дойдёт.
   Тело — `## Вопрос` / `## Ответ`; для задачи — `## Задача` / `## Эталон`, `starterCode`, `rubric`.
   Учитывай ограничение импортера для строк `#` внутри кода из общего стандарта.
5. Проверь редакционное качество и импорт; после успешного создания пометь идею
   `- [x] <title> — <difficulty> (<id>)`. ID обязателен для дедупликации.
6. Примени [interview-verify](../interview-verify/SKILL.md). Для записи в работающий сервис используй
   маршрут и проверку адреса из [ladder-topic](../ladder-topic/SKILL.md).

Файлы записывай нормализованно: `path.write_text(frontmatter.dumps(post) + "\n", encoding="utf-8")`.
Не добавляй поля `edges`/`sources`; ссылки помещай рядом с утверждениями в ответе.

## Пересобрать реестр по запросу

`regen_ledger.py` пересобирает `[x]` из графа и сохраняет `[ ]`-идеи:

```bash
API_URL=http://127.0.0.1:8000/api POOL=data-engineer python3 .claude/skills/interview-ideas/regen_ledger.py
```

Адрес и пул в команде — пример; перед запуском подставь фактические. Скрипт ожидает доступный API,
его группы ориентированы на data-engineer, порядок уровней фиксирован четырьмя стандартными,
а весь `[x]`-реестр заменяется содержимым выбранного пула. Запускай его только если реестр относится
целиком к этому пулу. Для смешанного реестра обновляй выбранные записи адресно; для закрытого пула
или своих уровней используй авторизованное чтение и порядок `pool.levels`, сохраняя остальные записи.
