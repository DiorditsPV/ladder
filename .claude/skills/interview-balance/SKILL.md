# Скилл: баланс и покрытие банка вопросов

Цель — показать, насколько банк сбалансирован по реальному дисбалансу стека (веса блоков —
`blocks[].weight` в `content/<pool>/pool.yaml`) и где дыры в матрице «под-колонка × сложность».

## 1. Снять покрытие (матрица + доли vs веса + пробелы)
```bash
python3 .claude/skills/interview-balance/coverage.py
```
Скрипт (stdlib, нужен сервер на :8000) печатает: матрицу «под-колонка × сложность», фактические доли
блоков против весов из `content/<pool>/pool.yaml` (колонка «дельта») и список пустых ячеек base/senior.
Env `API_URL` переопределяет адрес (по умолч. `http://127.0.0.1:8000/api`).
Пул задаётся `POOL=<id>` (по умолчанию `data-engineer`); контент — `content/<pool>/<block>/`.

## 2. Найти пробелы и перекосы
Отметь:
- **пустые ячейки** матрицы: под-колонка без `base` (нет обзорного «как работает X») или без `senior`
  (нет вопроса на trade-offs/масштаб) — типичные дыры;
- **перекос**: под-колонка с кучей middle и без junior/senior — нет лесенки сложности;
- **недобор по весу**: блок занимает меньше нод, чем диктует его вес.

## 3. Предложить (не плодить молча)
Сформируй краткий отчёт: матрица + список пробелов + предложения «добавить X в <subblock>/<difficulty>».
Конкретные новые вопросы **не генерируй здесь** — заведи их как идеи через скилл **interview-ideas**
(`- [ ]` в `Q_IDEAS.txt`, в нужную группу), либо предложи пользователю запустить генерацию.

## Заметки
- Уровни сложности: base (обзор/устройство) → junior → middle → senior.
- Под-колонки: frameworks → airflow|pyspark|dbt|streaming; databases → sql|dbms|storage|formats;
  python|platform — одна колонка.
- Не путать баланс (сколько вопросов где) с рефактором отдельных вопросов — это скилл interview-refactor.
