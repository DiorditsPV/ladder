## Проблема / цель
Минимапа React Flow сейчас красит все вопрос-ноды цветом блока — по ней не видно прогресса интервью.
Полезно с одного взгляда на минимапу понимать: что уже оценено, где сейчас «текущий» вопрос. Кодируем
прогресс в `nodeColor`: оценённые — серым, текущий — акцентом, остальные — цветом блока.

## Поведение / UX
- В минимапе (`<MiniMap nodeColor=…>`) цвет вопрос-ноды:
  - **текущий вопрос** (`data.current`) → акцент `#2563eb` (приоритет выше «оценён»);
  - **оценённый** (`data.score != null`) и не текущий → серый `#9ca3af`;
  - иначе → цвет блока (как сейчас, `BLOCK_COLOR[block]`).
- Не-вопрос ноды (фон/хедеры) — как сейчас (полупрозрачная заливка).
- Обновляется реактивно: оценил вопрос → его точка в минимапе сереет; сменил текущий → акцент переезжает.
- Крайние случаи: ничего не оценено и нет текущего → минимапа как раньше (блок-цвета). Текущий и
  оценённый одновременно (типично сразу после оценки) → акцент (текущий важнее для ориентации).

## Модель данных
Без изменений схемы. На уровне React Flow node-объекта вопрос-нодам добавлены `width/height` (= `CARD_W`/`CARD_H`
из `layout.ts`, которые раскладка и так использует для спейсинга) — нужно v12-минимапе для отрисовки нод.
`data` уже содержит `{ node, score, current, dimmed }`.

## Решения (с обоснованием)
- **Только `nodeColor`, без правки `buildNodes`** — нужные поля (`current`, `score`, `node.block`) уже в
  `data`; минимально-инвазивно, ноль риска для раскладки/типов.
- **Приоритет текущий > оценён** — для ведущего важнее видеть «где я сейчас»; точка-акцент одна, серых много.
- **Литеральные цвета `#2563eb`/`#9ca3af`** (а не CSS-переменные) — `nodeColor` это JS-функция, читать
  `var(--accent)` неудобно; минимапа — вторичный индикатор, контраст важнее тематирования. Совпадает с
  существующим стилем (там уже литералы `#999`).
- **Серый для оценённых** — нейтрально «сделано/убрано из фокуса»; акцент выделяется на фоне серых и
  блок-цветов.
