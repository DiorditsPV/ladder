## Проблема / цель
Сейчас увидеть «весь банк целиком» (все вопросы с ответами и критериями) можно только выгрузив печатный
HTML-файл (`bank-export`, на отдельной ветке) или листая канву по одной ноде через drawer. Нет режима
просмотра всего банка прямо в приложении: быстро найти вопрос текстом, отфильтровать по блоку/сложности/типу/тегу
и тут же прочитать ответ+критерии. Цель — отдельный in-app экран-оверлей «Все вопросы», читающий уже
загруженный `graph`, без скачивания файла.
Критерий пользы: ведущий за один клик открывает список всех вопросов, ищет по тексту, фильтрует и
разворачивает любой вопрос (ответ + критерии + starterCode) не уходя из приложения.

## Поведение / UX
- В шапке (`.session`-группа, рядом с «📥 Скачать») — кнопка `📋 Все вопросы`, открывающая полноэкранный
  оверлей `BankBrowser`.
- Оверлей (`.bankbrowser`, поверх канвы, как модалка):
  - **Шапка оверлея:** заголовок «Все вопросы», счётчик `показано N из M`, поле поиска (`.bankbrowser__search`),
    кнопка закрытия `✕` (и закрытие по `Esc`).
  - **Фильтры:** чип-тогглы по блокам (4), по сложности (base/junior/middle/senior), по типу (вопрос/задача).
    По умолчанию всё включено. Поиск — по `title`+`question`+`answer`+`topic`+`tags` (регистронезависимо, trim).
  - **Список:** сгруппирован по блокам в порядке `BLOCK_ORDER`, внутри блока — по под-колонкам (`subOf`/`SUB_LABEL`),
    внутри — по сложности (`DIFFS`-порядок), затем по id. Каждая строка (`.bankrow`): бейдж сложности
    (цвет `DIFF_COLOR`), бейдж типа (вопрос/задача), заголовок (`title` или первая строка `question`), теги.
  - **Раскрытие:** клик по строке разворачивает (`.bankrow--open`) тело: полный `question`, `answer`,
    список критериев `rubric` и `starterCode` (если есть, в `<pre>`). Несколько строк могут быть раскрыты
    одновременно (множество в state). Доп. кнопки «Развернуть всё / Свернуть всё».
  - **Пустой результат:** если фильтры/поиск ничего не дают — строка «Ничего не найдено».
- Скролл оверлея независим; канва под ним не интерактивна (оверлей перекрывает).

## Решения (с обоснованием)
- **Полноэкранный оверлей, не роут** — в приложении нет роутера (одностраничник, ReactFlow-канва).
  Оверлей по state `showBank` консистентен с `DetailDrawer`/fullscreen-паттернами и минимизирует диф.
  Отвергнут react-router — лишняя зависимость и архитектурный сдвиг ради одного экрана.
- **Собственные лёгкие фильтры в компоненте, а не общий filter-state канвы** — на канве фильтр «гасит» ноды
  (dimmed), семантика «просмотра банка» иная (показать/скрыть строки). Совместное состояние связало бы два
  разных UX; локальный state проще и безопаснее для гейта. Переиспользуем лейблы/цвета/группировку (не логику dimmed).
- **Множественное раскрытие + «развернуть всё»** — банк просматривают сканированием; одиночный аккордеон
  заставлял бы кликать назад-вперёд. Set раскрытых id дёшев.
- **Поиск по title+question+answer+topic+tags** — ведущий ищет и по формулировке, и по теме/тегу; узкий поиск
  «только по заголовку» бесполезен (у многих нод title пуст → fallback к первой строке question).
- **НЕ дублирует существующее:** `bank-export` — выгрузка печатного HTML-файла (офлайн-документ);
  `question-search` — подсветка/гашение на канве; здесь — отдельный экран просмотра всего банка в приложении.

- **Корректность:** блокеров нет (correctness-проход → `[]`). По ходу гейта найден и исправлен реальный баг:

    (также в App.tsx:146) — кандидаты на общий под-компонент/экспорт;
