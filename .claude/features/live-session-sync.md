# Фича: live-session-sync — синхронный показ оценок по сессии

## Идея
Один кандидат = одна сессия. Интервьюер и HR открывают **одну и ту же сессию** и видят
изменения оценок друг друга в реальном времени, без перезагрузки страницы.

## Затрагиваемые слои
- **backend/app/hub.py** (новый) — in-memory pub/sub по `session_id` (asyncio-очереди подписчиков).
- **backend/app/main.py** — SSE-эндпоинт `GET /api/sessions/{id}/events`; `POST .../score`
  становится `async` и публикует обновлённый снимок сессии в hub.
- **frontend/src/api.ts** — `listSessions()`, `eventsUrl(id)`.
- **frontend/src/App.tsx** — подписка на `EventSource`, слияние входящих оценок в `scores`;
  авто-подключение по `?session=<id>` из URL; пикер «Подключиться» к существующей сессии;
  индикатор `LIVE`; кнопка «Выйти».
- **frontend/src/styles.css** — стили индикатора и пикера.

## Модель данных
Без изменений схемы БД. Снимок сессии (`{id, candidate, created_at, scores}`) — уже отдаётся
`get_session`. Hub рассылает этот же снимок целиком (идемпотентное слияние на клиенте).

## Транспорт
**SSE** (Server-Sent Events) — однонаправленный server→client, нативный `EventSource`,
авто-реконнект, без новых зависимостей. События:
- `event: snapshot` — текущее состояние при подключении;
- `event: update` — новый снимок после каждой оценки;
- `: keepalive` каждые ~15 c (держит соединение, детектит обрыв).

## UX
- Старт сессии → URL получает `?session=<id>` (share-ссылка).
- Открытие той же ссылки (или выбор в пикере) → подгружает оценки + подписывается на live.
- Бейдж `🟢 LIVE` при активном соединении (серый при обрыве/реконнекте).
- Локальная оценка остаётся оптимистичной; снимок с сервера сливается объединением
  (`{...prev, ...server}`) — без потери только что выставленной локальной оценки.

## Риски
- Несколько процессов uvicorn ⇒ in-memory hub не общий. Деплой — один процесс, ок.
- Гонки оценок: сервер сериализует записи, рассылает **полный** снимок → побеждает последний
  полный снимок, потерь нет.

## План
1. `hub.py` — `SessionHub` (subscribe/unsubscribe/publish).
2. `main.py` — SSE-эндпоинт + публикация в `set_score`.
3. Тесты: list-сессий, snapshot из SSE.
4. Фронт: api + App (EventSource, URL, пикер, LIVE) + css.
5. interview-verify: import → pytest → build → smoke.
