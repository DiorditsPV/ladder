## Проблема / цель
Сейчас «Дальше →» и стрелки навигируют по ВСЕЙ сетке (`placement.order`), игнорируя активные фильтры — можно
перейти на погашенную (dimmed) фильтром ноду, которая визуально не видна и не выбирается мышью. Ведущий
включил фильтр (блок/сложность/тип/теги), а навигация всё равно «проваливается» в скрытое. Нужно: «Дальше» и
стрелки ходят ТОЛЬКО по видимым (не-dimmed) нодам.

## Поведение / UX
- **«Дальше →» / `n`**: следующий НЕоценённый среди ВИДИМЫХ нод по порядку сетки (с переносом по кругу);
  если невидимых-неоценённых нет — следующая любая видимая. Если видимых нет вовсе (всё отфильтровано) — no-op.
- **Стрелки** ↑↓←→: переходят к ближайшей ВИДИМОЙ ноде в направлении (пропускают dimmed):
  - ↑/↓ — сканируют колонку от текущей строки в направлении, ища следующий видимый id;
  - →/← — сканируют колонки в направлении, в каждой берут видимый id около текущей строки (если есть).
  - Нет текущего → первый видимый в порядке сетки.
- Крайние случаи: текущий стал dimmed (сменили фильтр) — навигация всё равно отталкивается от его позиции в
  сетке и находит ближайший видимый; всё отфильтровано — стрелки/«Дальше» ничего не делают.

## Затрагиваемые слои и файлы
- backend: нет.
- frontend: `App.tsx` — (1) memo `visibleIds: Set<string>` тем же предикатом, что `dimmed` в `buildNodes`
  (block/diff/kind/tag); (2) `nextQuestion` — фильтровать кандидатов по `visibleIds`; (3) клавиатурный эффект
  (стрелки) — пропускать не-видимые при сканировании; добавить `visibleIds` в deps обоих.
- content: нет.
- tests: `frontend/smoke.mjs` — включить тег-фильтр (гасит часть), нажать `n` → текущий вопрос НЕ dimmed
  (навигация осталась среди видимых).

## Модель данных
Без изменений (UI-стейт; `visibleIds` считается из `graph` + активных фильтров).

## Решения (с обоснованием)
- **`visibleIds` отдельным memo, предикат идентичен `dimmed`** — держать «видимость» в одном смысле с гашением
  карточек. (На `main` `dimmed = block/diff/kind/tag`; на интеграции есть ещё track/query/unscored — но эта
  ветка от `main`, поэтому предикат — block/diff/kind/tag. Комментарием отметить «держать в синхроне с dimmed».)
- **«Дальше» сохраняет приоритет «неоценённый», но в пределах видимых** — поведение ведущего не меняется, лишь
  ограничивается видимым набором.
- **Стрелки — сканирование с пропуском dimmed**, а не «прыжок на первый видимый» — сохраняет
  пространственную логику (вверх/вниз по колонке, влево/вправо по колонкам).
- **Пустой видимый набор → no-op** — не дёргать текущий, не падать.

## План реализации (чеклист для feature-build)
1. [ ] **visibleIds**: в `App.tsx` `const visibleIds = useMemo(() => Set отобранных по
   block/diff/kind/tag, [graph, activeBlocks, activeDiffs, activeKinds, activeTags])`. Коммит
   `feat(filter-aware-nav): visibleIds memo`.
2. [ ] **nextQuestion**: кандидаты только `visibleIds.has(id)`; приоритет неоценённый → fallback любой видимый;
   пустой набор → return. + `visibleIds` в deps. Коммит `feat(filter-aware-nav): «Дальше» over visible only`.
3. [ ] **arrows**: в клавиатурном `onKey` ↑↓ сканируют колонку до следующего видимого; →← ищут колонку с
   видимым около row; старт (нет current) = первый видимый; + `visibleIds` в deps эффекта. Коммит
   `feat(filter-aware-nav): arrow keys skip dimmed`.
4. [ ] **smoke**: тег-фильтр → `n` → `.qnode--current` не имеет класса `qnode--dimmed`. Коммит
   `test(filter-aware-nav): smoke`.

## Риски / открытые вопросы
- Рассинхрон `visibleIds` с `dimmed` при будущих правках фильтров — снижаем комментарием; общий хелпер
  `passesFilters(n)` — на будущее.
- Если текущий стал невидимым и видимых в его колонке/строке нет — стрелка может «не сработать» (ожидаемо;
  «Дальше» уведёт на первый видимый).
