# FEATURE_IDEAS.md — бэклог фич для автогенерации

Источник идей для луп-пайплайна (feature-design → feature-build). Контекст «что уже сделано» —
в `FEATURES.md`; спроектированные спеки — в `.claude/features/<slug>.md`.

**Легенда:** `[ ]` — не реализована, `[x]` — реализована (в скобках ветка `feature/<slug>`).
**Правила:** одна идея = один `slug` (kebab-case). Дедуп по slug. Не дублируй то, что уже в `FEATURES.md`.
Формат: `- [ ] <slug>: <краткое описание> — <подсказка по слоям/объёму>`.

## Продающие фичи (платная версия)
Отдельный блок paid-тира. Логика монетизации: **free** = один интервьюер локально; **paid** = команда / облако / интеграции.
Формат строки: `slug` · **ценность** (за что платят) · _объём по слоям_ — последнее остаётся подсказкой для feature-design/feature-build.

- [ ] team-workspace — **командное облако: история всех кандидатов и общий банк в одном месте, а не на ноутбуке каждого; роли и доступы.** Платит компания/рекрут-команда, это база для остальных paid-фич. _backend: auth (JWT/OAuth), мульти-тенант, миграция SQLite→Postgres, RBAC; фронт: логин, переключатель воркспейса._
- [ ] live-panel — **панельные и удалённые интервью без рассинхрона: несколько интервьюеров на одной доске в реальном времени, синхрон оценок/заметок, сведение панельных баллов.** Платят распределённые команды. _backend: websockets, presence; фронт: индикаторы присутствия, merge оценок._
- [ ] ats-integration — **вписывается в существующий HR-процесс: скоркарты и отчёты улетают прямо в карточку кандидата в ATS, нет двойного ввода.** Снимает главный барьер внедрения в компании. _backend: коннекторы/вебхуки к Greenhouse/Lever/Huntflow, OAuth провайдеров, календарь._
- [ ] white-label-reports — **отчёт под брендом компании/агентства: лого, цвета, кастомные секции, batch-экспорт по нескольким кандидатам, защищённая ссылка вместо PDF.** Прямо продаваемая ценность для рекрут-агентств. _расширение src/report.ts + backend share-link._

## Интеграции с внешними системами (РФ)
Тема — встраивание в инфраструктуру российских компаний (СХД/диски, CRM, ERP/HRM, ATS, SSO, мессенджеры, ВКС). Без интеграций решение не внедряют (двойной ввод) — это одна из важнейших тем для продаж в РФ.
**Полное исследование (карта рынка, приоритеты, архитектура, compliance):** [`docs/integrations/`](docs/integrations/README.md). Приоритеты ниже — оттуда; перед реализацией пройти [`docs/integrations/_verify.md`](docs/integrations/_verify.md).

- [ ] integration-hub — **(P0, фундамент)** коннектор-платформа: реестр коннекторов, хранилище токенов/секретов, маппинг полей, диспетчер вебхуков с очередью и ретраями, журнал интеграций. Без неё каждая интеграция — спагетти. _backend: интерфейс Connector + очередь + секреты; опирается на team-workspace._
- [ ] ats-huntflow-sync — **(P0, якорь)** двусторонняя синхронизация с Huntflow (де-факто стандарт ATS в РФ): импорт кандидатов/вакансий, обратная запись скоркарта/статуса/ссылки на отчёт. _backend-коннектор (OAuth, вебхуки, маппинг), модель session↔external_candidate; фронт — привязка и индикатор синка. См. docs/integrations/ats-recruiting.md._
- [ ] hh-jobboards-import — **(P1)** импорт вакансий и откликов/резюме из hh.ru (главный источник кандидатов), задел под Avito Работа/SuperJob. _backend-коннектор hh.ru (OAuth работодателя), парсер резюме. См. ats-recruiting.md._
- [ ] scheduler-page — **(P1, UX-ядро)** отдельная страница-расписание («Сегодня»/неделя): кандидат появляется при назначении встречи (время, позиция, трек), **кнопка «Начать интервью» ведёт прямо в доску** с уже привязанной сессией. Ценность даже без внешнего календаря (внутренние слоты). _модель Meeting/Slot (кандидат, время, интервьюер, трек, session_id); backend CRUD слотов; фронт — страница-календарь день/неделя + глубокая ссылка слот→`/board?session=…`. См. docs/integrations/calendar-email.md._
- [ ] calendar-email-sync — **(P1)** синхронизация с корпоративным календарём и почтой: CalDAV/ICS (Яндекс/VK/МойОфис), SMTP/IMAP — ICS-инвайты кандидату/интервьюеру, двусторонний синк встреч, занятость интервьюеров, RSVP. Навешивается поверх scheduler-page. _backend: провайдер календаря (CalDAV/ICS база + REST Яндекс/VK) и почты (SMTP/IMAP) за единым интерфейсом; опирается на integration-hub. См. calendar-email.md._
- [ ] sso-ru-identity — **(P1)** корпоративный вход поверх team-workspace: OIDC/SAML (Keycloak, ADFS, ALD Pro), LDAP (Active Directory), соц-провайдеры Yandex ID / VK ID; маппинг групп→роли. Требование любого enterprise. _backend: провайдеры аутентификации за единым интерфейсом. См. sso-identity.md._
- [ ] storage-ru-disks — **(P1)** внешнее хранилище артефактов сессии: Яндекс 360 / VK WorkDisk / МойОфис / S3-совместимое (Yandex Object Storage, VK Cloud, Selectel, MinIO). И удобство, и 152-ФЗ. _backend: провайдер-хранилища за единым интерфейсом (S3 база + WebDAV/REST). См. storage-docs.md._
- [ ] notify-telegram-vkteams — **(P1, дёшево/заметно)** уведомления и боты: Telegram / VK Teams / Пачка — напоминания о слотах, статусы по сессии, быстрые действия. _backend: провайдер-нотификаций (Telegram Bot API первым) + шаблоны. См. messaging-video.md._
- [ ] crm-bitrix-amocrm — **(P2)** экспорт результата интервью в Bitrix24/amoCRM (карточка/сделка + отчёт + статус). Для рекрут-агентств — воронка кандидатов. _backend-коннектор (вебхуки Bitrix24 / REST amoCRM). См. crm-erp.md._
- [ ] erp-1c-hrm — **(P2)** обмен с 1С:ЗУП/1С:ERP: передача нанятого (hire) в кадровый учёт, импорт справочников должностей/подразделений. Закрывает процесс «от интервью до трудоустройства». _backend-адаптер 1С (OData/HTTP-сервисы), проектируется под конфигурацию заказчика. См. crm-erp.md._
- [ ] video-vks-ru — **(P2)** видеоинтервью из доски: Яндекс Телемост / TrueConf / Контур.Толк / VK Звонки — создание встречи, ссылка в сессии, приглашение. _backend: провайдер ВКС за единым интерфейсом. См. messaging-video.md._
- [ ] compliance-rf — **(P1 для гос/крупных)** пакет соответствия: согласие на обработку ПД, политика хранения/удаления, режим on-prem (PostgreSQL + MinIO + Keycloak), подготовка к реестру российского ПО, журналирование. Блокер для B2G. _инфраструктурно-юридический трек, не коннектор. См. compliance-rf.md._
